## Critical Gaps

Blocking issues that prevent production readiness:

1. **All 3 presets fail manifest validation (stale enum values)**
   - **Why it blocks:** The presets are the user-facing quick-start artifacts. Every one of them (`01-web-tier.yaml`, `02-database-tier.yaml`, `03-bastion.yaml`) fails `planton validate-manifest` with `invalid value for enum field access: "Allow"`. They were written against the old string-typed spec (`Inbound`/`Allow`/`Tcp`/`"*"`); the reworked spec uses closed proto enums that require the enum names `INBOUND`/`ALLOW`/`TCP`/`ANY`. A user copying any preset gets an immediate load error.
   - **What to do:** Rewrite the enum-valued fields in all three preset YAMLs (`direction: INBOUND`, `access: ALLOW|DENY`, `protocol: TCP|ANY`; replace `protocol: "*"` with `protocol: ANY`) and update the companion `.md` files. Re-verify with `go run . validate-manifest <preset>`.
   - **Files:** `presets/01-web-tier.yaml`, `presets/02-database-tier.yaml`, `presets/03-bastion.yaml` (+ `.md` companions)

2. **Undocumented cross-engine tag divergences (cosmetic; caps IaC categories at Partial)**
   - **Why it blocks:** The same manifest deployed via Pulumi vs Terraform gets different Azure tags. See Category 5b for the field-by-field detail.
   - **What to do:** Pick the canonical rule (the Pulumi lowered-enum-string convention and id-only-when-set are the platform grain elsewhere) and align `iac/tf/locals.tf`, or add a documented `PARITY-EXCEPTION:` in BOTH modules.
   - **Files:** `iac/tf/locals.tf`, `iac/pulumi/module/locals.go`

3. **User-facing docs contradict the reworked component**
   - **Why it blocks:** `README.md`, `catalog-page.md`, `docs/README.md`, and both IaC READMEs still describe the pre-rework design: string-typed direction/access/protocol with mixed-case values, outputs named `nsg_id`/`nsg_name` (now `network_security_group_id`/`network_security_group_name`), "80/20 omissions" listing plural port ranges / ASG ids / `AH`+`ESP` as skipped (all now implemented), and "separate rules, not inline" (the Pulumi module now deliberately uses inline rules). Every YAML example in `catalog-page.md` would fail validation today.
   - **What to do:** Sweep all five docs to match the current spec/outputs. The `docs/README.md` "Design Rationale" sections need rewriting, not just find-replace — the enum and inline-rule decisions were reversed.
   - **Files:** `README.md`, `catalog-page.md`, `docs/README.md`, `iac/pulumi/README.md`, `iac/tf/README.md`

### 5b. Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ⚠️** — two undocumented, cosmetic tag divergences; nothing misdeploys.

Compared engines: Pulumi (`iac/pulumi/module/`) and Terraform (`iac/tf/`), both judged against `spec.proto` + `stack_outputs.proto`. Output parity verified with `planton validate-outputs` (2/2 proto fields populated, zero unmapped) and the green `AzureNetworkSecurityGroup` case in `pkg/outputs/conformance_test.go`.

**Legend:** ✅ MATCH | ⚠️ DIVERGES (undocumented) | 🔵 EXCEPTION (documented)

✅ **In parity:** scope source, naming basis, base tag keys and merge order, full spec feature coverage (every field of the reworked spec honored by both engines with identical unset semantics), enum mapping, dependency ordering, and stack outputs (machine-verified).

⚠️ **Divergences (undocumented):**

- **`resource_kind` tag value** — Pulumi writes the lowered enum string `azurenetworksecuritygroup`; Terraform writes the literal `azure_network_security_group`. Impact: cosmetic — the same resource carries a different governance tag depending on the provisioning engine, which breaks tag-based cost/policy grouping across engines but deploys the correct NSG. (Same drift pattern the AzurePublicIpPrefix audit flagged; it repeats across the Azure Tf modules — `azurenatgateway`, `azurepublicip` — so fixing it is a family-level decision.)
- **`resource_id` tag presence** — Terraform always emits `resource_id` (falling back to `metadata.name` when id is empty); Pulumi emits it only when `metadata.id` is set. Impact: cosmetic tag drift.

🔵 **Documented exception:**

- **Inline vs standalone rule modeling** — both modules carry explanatory comments referencing the other engine and asserting identical ARM state (and the Terraform side's plan-time conflict detection). This qualifies in substance as a documented, output-neutral exception; it does not use the literal `PARITY-EXCEPTION:` marker, which should be added for greppability.

**Effect on score:** caps Categories 4 & 5 at ⚠️ Partial (−0.50 / −0.30). No divergence would misdeploy, so not ❌.
