### ⚠️ Divergences (undocumented)

1. **`large_file_share_enabled` — unset/false handling** — Terraform always sends the value
   (`optional(bool, false)` → an explicit `false` reaches azurerm), while Pulumi sends it
   only when `true` (omits otherwise). On a fresh create the ARM payload is identical
   (azurerm's Create drops `false` — the API rejects `Disabled`). The engines diverge on the
   enable→disable transition: azurerm's CustomizeDiff forces **account replacement** when
   the value goes true→false (matching the spec comment "disabling replaces the account"),
   which Terraform will plan — while Pulumi, never sending `false`, silently leaves the
   feature enabled. Impact: day-2 transition only; identical stack-inputs deploy identical
   objects. Fix: align Pulumi to always send the bool (or add a `PARITY-EXCEPTION:` to both
   modules choosing the omit-when-false behavior deliberately).

2. **Tag-shape exception documented in ONE module only** — `iac/tf/locals.tf` carries a
   `PARITY-EXCEPTION:` for the `resource_kind` value (`azure_storage_account` literal vs
   Pulumi's lowered enum string `azurestorageaccount`) and the `resource_id` fallback
   (metadata.name vs omitted). The exception is output-neutral and family-wide, but the rule
   requires the comment in BOTH modules; `iac/pulumi/module/locals.go` has no matching
   comment. Fix: add the mirrored `PARITY-EXCEPTION:` comment to the Pulumi locals.

**Effect on score:** caps Categories 4 & 5 at ⚠️ Partial. Neither divergence misdeploys for
identical fresh stack-inputs, so the gate is ⚠️, not ❌.
