## Schema Coverage vs azurerm v4.80 (`container_app_environment_dapr_component_resource.go`)

All provider fields modeled: environment FK, name (as `component_name`, the
provider's name contract as a CEL), `component_type` (deliberately open --
Dapr's component catalog evolves independently and the provider does not
validate it), `version`, `init_timeout` (the provider's `InitTimeout`
interval format `[0-9]+[smh]` as a CEL, default "5s"), `ignore_errors`
(default false, fail-loud posture documented), secrets (the provider expands
these as Dapr name/value secrets -- deliberately NOT the app-level secret
schema, which this ARM resource does not support), metadata (value XOR
secret_name CEL), and scopes.

both front-loaded. Component-type/metadata correctness is a Dapr-runtime
contract that surfaces at sidecar initialisation, not at apply (documented in
the research notes).
