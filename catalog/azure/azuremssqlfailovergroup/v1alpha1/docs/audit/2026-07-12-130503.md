## Apply-Time Validator Source-Diff

Read `mssql_failover_group_resource.go` Arguments + CustomizeDiff +
Create/Update:

- **AUTOMATIC requires grace_minutes ≥ 60; MANUAL forbids it**
  (CustomizeDiff, both branches): front-loaded as the
  `failover_grace_minutes_pairing` message CEL, both directions.
- **grace_minutes IntAtLeast(60)** (schema): subsumed by the pairing CEL.
- **name contract** (`ValidateMsSqlFailoverGroupName`:
  `^[0-9a-z]([-0-9a-z]{0,61}[0-9a-z])?$`): front-loaded as the
  `failover_group_name_format` CEL (1-63 lowercase/digits/hyphens, no
  leading/trailing hyphen) -- character-for-character the provider's
  regex.
- **read-only endpoint default** (create/update send
  ReadOnlyEndpointFailoverPolicy DISABLED when the flag is unset -- the
  schema is Optional+Computed with no Default, and the model's zero value
  is false): the audit CORRECTED the shipped docs here -- the spec
  comment, both module comments, README, docs, and catalog page had
  claimed "Azure default enabled". All five now state the honest
  contract: unset ⇒ Disabled. Both engines omit the argument when unset,
  so behavior was already identical; only the documentation was wrong.
- **partner id** (`azure.ValidateResourceID`): carried by the FK seam
  (references resolve to real ARM ids).
- No spec CEL invents a rule the provider and ARM do not enforce.
