### 5b. Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

Compared engines: Pulumi (`iac/pulumi/module/`) and Terraform (`iac/tf/`),
both judged against `spec.proto` + `stack_outputs.proto` (neither privileged).
Verified outputs with `planton validate-outputs` — full proto population,
zero unmapped: **yes** (4/4 fields).

| Dimension | Pulumi | Terraform | Verdict |
|-----------|--------|-----------|---------|
| Scope source (RG + VNet name) | parsed from `virtual_network_id` ARM id (`parseVirtualNetworkId`, case-insensitive) | parsed from same field (`regex()` with `(?i)`) | ✅ MATCH |
| Resource naming basis | `spec.name` (both the Pulumi URN and the ARM `Name` arg) | `var.spec.name` | ✅ MATCH |
| Labels / tags | none — ARM peerings are untaggable (documented in both modules) | none, same comment | ✅ MATCH |
| Pod/service selectors | N/A (not a Kubernetes kind) | N/A | ✅ MATCH |
| Spec feature coverage (all 11 fields) | name, both FK networks, 4 connectivity bools, complete-vs-subnet-scoped, both subnet lists, IPv6-only | identical set | ✅ MATCH |
| Empty-list / unset handling | empty subnet lists omitted; `only_ipv6_peering_enabled` sent only when true | `null` for empty lists; `true : null` for IPv6-only | ✅ MATCH |
| Dependency ordering | single resource, no edges | single resource, no edges | ✅ MATCH |
| Stack outputs → proto | `peering_id`, `peering_name`, `virtual_network_name`, `resource_group_name` | identical names, same derivations | ✅ MATCH |

**Legend:** ✅ MATCH | ⚠️ DIVERGES (undocumented) | 🔵 EXCEPTION (documented `PARITY-EXCEPTION:`)

✅ **In parity:**

- All eight dimensions above. The `pkg/outputs/conformance_test.go` case for
  `AzureVirtualNetworkPeering` exists and passes (`go test ./pkg/outputs/ -run
  TestStackOutputsConformance` → ok), and the ad-hoc guard confirms 4/4 proto
  fields populate through the generic reflection transformer with nothing
  unmapped.

⚠️/❌ **Divergences (undocumented):** None.

**Observation (not a divergence on any supported path):** the two engines
encode the proto `(options.default)` bool defaults differently. Terraform
carries module-level fallbacks (`optional(bool, true)` for
`allow_virtual_network_access` / `peer_complete_virtual_networks_enabled`),
while Pulumi relies on the defaults being applied upstream
(`spec.GetAllowVirtualNetworkAccess()` returns `false` for an unset field).
On every supported path the defaults ARE applied before the module runs — the
CLI manifest loader (`internal/manifest/protodefaults.ApplyDefaults`) and the
platform's create/update defaults applier both populate the fields, so both
engines receive explicit values and behave identically (the Pulumi module
documents this assumption inline). The only hole is a hand-crafted stack-input
fed directly to the Pulumi binary with those fields omitted, which is a dev
convenience path, not a deploy path. Recommended hardening (low priority):
mirror the `Auth0Client` precedent from `pkg/iac/MODULE_PARITY.md` and encode
an else-true fallback in the Pulumi module so the engines are symmetric even
on unsupported inputs. This matches the current family pattern (e.g.
`AzureSubnet` does the same), so it is recorded as an observation, not a
defect.

**Effect on score:** none — Categories 4 and 5 keep full credit.
