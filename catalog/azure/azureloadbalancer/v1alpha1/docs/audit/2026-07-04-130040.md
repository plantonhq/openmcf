   - **Why:** Restores PARITY ✅ and the full score. Every other enum in the module goes through a full-proto-name → ARM-value map; this is the one that doesn't.

## Critical Gaps

1. **Terraform passes the raw `synchronous_mode` proto enum name to the azurerm provider (parity defect)**
   - **Why it blocks:** The tfvars renderer emits enum fields as their FULL proto value names (protojson), so Terraform receives `"AUTOMATIC"` / `"MANUAL"`. `main.tf` line 51 passes that string verbatim to `azurerm_lb_backend_address_pool.synchronous_mode`, whose provider schema validates case-sensitively against `["Automatic", "Manual"]` (azurerm v4.x `lb_backend_address_pool_resource.go`, `StringInSlice(PossibleValuesForSyncMode(), false)`). The plan fails for any spec that sets the field. The Pulumi module maps the enum correctly (`main.go` lines 189-193: `AUTOMATIC → "Automatic"`, `MANUAL → "Manual"`), so the same manifest deploys on one engine and errors on the other — an undocumented, outcome-changing divergence.
   - **What to do:** Add the enum map in `iac/tf/locals.tf` and route `main.tf` line 51 through it (exact patch under Quick Wins). Then re-run `tofu validate` and, ideally, a plan with a `synchronous_mode`-bearing tfvars. No proto, Pulumi, output, or doc change is needed.
   - **File:** `iac/tf/main.tf` (line 51), `iac/tf/locals.tf` (missing map)
