## Addendum (same day): live E2E deferred on Azure's certificate-content rule

The live dual-engine run surfaced a second apply-time contract, now
recorded in the spec comment, docs/README, user README, and catalog
page: **Azure rejects self-signed certificates for Front Door BYO TLS**
(`BadRequest: "The certificate chain includes an invalid number of
certificates. The number of certificates should be at least 2."`) --
the wrapped certificate must be CA-issued with a complete chain. The
fixture certificate (the Key Vault kind's self-signed smoke cert)
therefore cannot pass, and the test tenant has no CA to mint a valid
one; the E2E profile records the deferral with the unblock path. The
run still live-proved the fixture chain, the harness's Front Door
service-principal bootstrap (the create reached ARM's content
validator -- no authorization error), the module's request shape, and
clean teardown including the vault purge. Offline gate unchanged.
**PARITY ✅ COVERAGE ✅ stand.**
