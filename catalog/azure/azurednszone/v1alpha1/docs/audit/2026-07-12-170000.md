# Audit Report: AzureDnsZone

**Date:** 2026-07-12-170000

**Mode:** full audit with `--parity` focus (breaking rework)

## Summary

**Score: 100% -- Fully Complete. PARITY ✅ COVERAGE ✅**

Reworked from a bundled zone-plus-records spec to the zone-only kind at
the full azurerm v4.80 `azurerm_dns_zone` surface (DNS API 2018-05-01):
the SOA record fold (email + all six writable timers/serials + record
tags), user tags, and the delegation-grade output surface
(`name_servers`, `max_number_of_record_sets`, the `zone_name` +
`resource_group_name` addressing pair). The bundled `records` list --
whose modules HARDCODED SRV priority/weight/port, CAA flags/tag, and a
single MX preference -- is dissolved; records are standalone
`AzureDnsRecord` resources. Both engines migrated onto the shared
provider builder (the Pulumi module previously inlined
`azure.NewProvider`, which silently broke keyless OIDC auth).

## Apply-Time Validator Source-Diff

Read `dns_zone_resource.go` (typed resource, schema + Create/Update) and
`validate/dns_zone_soa_record_email.go`:

- **SOA email validator** (2-34 dot-separated segments, no empty
  segment, each <=63 chars, `[a-zA-Z0-9._-]` alphabet) -- front-loaded
  verbatim as the `azure_dns_zone_soa_email_format` CEL.
- **The unconditional create/update check** `len(zone_name) +
  len(trimmed_email) <= 253` -- front-loaded as the
  `azure_dns_zone_name_plus_soa_email_length` message CEL.
- **SOA host preservation**: the provider GETs the API-assigned SOA host
  and writes it back unchanged -- which is why `host_name` is not
  modeled (Azure-owned).
- Location is hardcoded `global` by the provider (zones are global) --
  matches the spec's no-region design.
- No CustomizeDiff; no other create-path validators. No spec CEL invents
  a rule the provider does not enforce (the zone-name CEL mirrors DNS's
  own label grammar, which ARM enforces at create).
