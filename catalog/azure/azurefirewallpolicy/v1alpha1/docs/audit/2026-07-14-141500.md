## Apply-Time Validator Source-Diff

Read `firewall_policy_resource.go` (schema lines 662-1015 +
`resourceFirewallPolicyCreateUpdate` lines 60-157) and
`validate/firewall_policy_name.go`:

- **NO CustomizeDiff exists** and the create path carries no SKU
  validation -- Premium-only features (IDPS, TLS) are rejected only by
  ARM. Front-loaded here as the two root-message CELs
  (`intrusion_detection_requires_premium`,
  `tls_certificate_requires_premium`), justified by ARM's documented
  Premium contract and the provider's own fixture separation
  (`completePremium` is the only fixture carrying either block).
- **Name regex** `^[^\W_][\w-.]*[\w]$` mirrored as the
  `firewall_policy_name_format` CEL (incl. the implicit 2-char minimum).
- **`auto_learn_private_ranges_enabled` one-way semantics** (provider
  `GetOk` skips false; only "Enabled" is ever written): both engines send
  the flag only when true.
- **Identity TypeNone guard** (provider leaves identity nil): the spec
  models the block as optional; both engines send it only when present.
- **`threat_intelligence_allowlist` AtLeastOneOf** mirrored as a message
  CEL.
- **Explicit-proxy port bound 0-35536** (the provider's published
  validator, an apparent typo for 65535 but the ENFORCED bound):
  mirrored, quirk documented in spec + research docs.
- No spec CEL invents a rule the provider and ARM do not enforce
  (Basic-tier feature restrictions are documented, not CEL'd -- not
  verifiable from the provider source).
