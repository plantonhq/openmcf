## Category 5b: Cross-Engine IaC Parity (the gate this audit leads with)

Field-by-field sweep of `iac/tf/` vs `iac/pulumi/module/` against
`spec.proto` + `stack_outputs.proto`:

- **Resource surface identical**: one
  `azurerm_web_application_firewall_policy` / `waf.Policy` carrying
  custom rules, managed rules, and policy settings.
- **Enum vocabularies exhaustive and identical on both engines**: 11
  vocabularies (rule types, custom-rule actions, rate windows, rate
  grouping, match variables, 12 operators, 7 transforms, rule-set types,
  5 override actions, 9 exclusion variables, 5 selector operators, 6
  scrubbing variables, modes) carried as complete maps in `locals.tf`
  and `locals.go` — a missing entry cannot silently drop a rule.
- **Materialized defaults identical**: unspecified rule-set type →
  `OWASP`, unspecified mode → `Prevention`, unspecified scrubbing
  operator → `Equals`, excluded-rule-set version → `3.2` — each
  azurerm's own default, sent explicitly by BOTH engines so the ARM
  payloads converge.
- **Presence-guard sweep clean**: every optional-with-default dial
  (rule/scrubbing `enabled`, all 9 policy-settings fields) falls back to
  its documented default explicitly on the Pulumi side, mirroring the
  Terraform `optional(...)` defaults. `file_upload_enforcement` is
  forwarded only on explicit presence on BOTH engines (OWASP-3.2-only
  field; a materialized default would error on older rule sets).
- **Outputs identical**: `policy_id`, `policy_name` — confirmed
  populated 2/2 live on both engines.
- **Documented exception (family-wide, output-neutral)**: the
  metadata-derived tag shape carries the standing `PARITY-EXCEPTION`
  comment in BOTH modules.
