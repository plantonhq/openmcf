## Critical Gaps

None that block release (nothing silently misdeploys differently per engine, and both builds/tests/validate pass). The parity-gate findings below must be addressed to reach PARITY ✅:

1. **`sku_profile.vm_sizes[].rank` — engines diverge; exception documented one-sided**
   - **Why it blocks the gate:** Terraform provisions ranked `virtual_machine_size` blocks (azurerm v4 supports ranks); the pinned pulumi-azure v6.38.0 SDK's `OrchestratedVirtualMachineScaleSetSkuProfileArgs` carries plain `VmSizes` strings only, so the Pulumi module fails loudly on any ranked profile. The `PARITY-EXCEPTION:` note exists only in the Pulumi module — the convention requires it in BOTH.
   - **What to do:** Mirror the exception comment into `iac/tf/main.tf`, or upgrade the Pulumi SDK when it exposes ranks and wire them in.
   - **File:** `iac/pulumi/module/flexible.go` (lines 40-55), `iac/tf/main.tf` (lines 620-633)

2. **`data_disks[].name` silently dropped in the FLEXIBLE branch (both engines)**
   - **Why it blocks the gate:** The spec does not gate the field to UNIFORM, so it is legal on a FLEXIBLE set — yet neither engine maps it there (the orchestrated resource has no data-disk `name` in the azurerm schema or the Pulumi SDK). A user-declared disk name is silently ignored. Cross-engine behavior is identical, but the proto contract is broken without a gate or a documented drop.
   - **What to do:** CEL-gate `data_disks[].name` as UNIFORM-only (matching ARM's actual surface), or document the drop in both modules.
   - **File:** `spec.proto` (line 797), `iac/tf/main.tf` (753-766), `iac/pulumi/module/flexible.go` (237-257)

3. **`extensions[].automatic_upgrade_enabled` silently dropped in the FLEXIBLE branch (both engines)**
   - **Why it blocks the gate:** Same class as the previous item — the orchestrated extension schema has no `automatic_upgrade_enabled` (azurerm and Pulumi SDK alike); both engines send it only in the UNIFORM branches, with no CEL gate and no comment. `automatic_upgrade_enabled: true` on a FLEXIBLE set validates and silently does nothing.
   - **What to do:** CEL-gate the field UNIFORM-only, or document the drop in both modules.
   - **File:** `spec.proto` (line 1223), `iac/tf/main.tf` (874-897), `iac/pulumi/module/flexible.go` (408-437)
