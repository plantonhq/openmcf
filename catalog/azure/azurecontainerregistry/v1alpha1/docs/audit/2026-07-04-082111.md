### 5b. Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

Compared engines: Pulumi (`iac/pulumi/module/`) and Terraform (`iac/tf/`), both judged against `spec.proto` + `stack_outputs.proto` (neither privileged). Outputs verified with the automated guard, not by eye: `planton validate-outputs --kind AzureContainerRegistry --module-dir iac/tf --sample-outputs <representative>.json` → **7/7 proto fields populated, zero unmapped**, and the per-kind case in `pkg/outputs/conformance_test.go` **passes** (`go test ./pkg/outputs/ -run TestStackOutputsConformance` → ok).

| Dimension | Pulumi | Terraform | Verdict |
|-----------|--------|-----------|---------|
| Scope source (region + resource group) | `spec.region`, `spec.resource_group.GetValue()` | `var.spec.region`, `var.spec.resource_group` | ✅ MATCH |
| Resource naming basis | ARM name = `spec.registry_name` | ARM name = `var.spec.registry_name` | ✅ MATCH |
| Tags (keys + values) | metadata-derived + user tags merged over | same merge order | 🔵 EXCEPTION (documented) |
| Pod/service selectors | n/a (no Kubernetes workload) | n/a | ✅ MATCH |
| Spec feature coverage | all 19 spec fields honored | all 19 spec fields honored | ✅ MATCH |
| Dependency ordering | single resource, no edges | single resource, no edges | ✅ MATCH |
| Stack outputs → proto | 7/7 fields, same names | 7/7 fields, same names | ✅ MATCH |

**Legend:** ✅ MATCH | ⚠️ DIVERGES (undocumented) | 🔵 EXCEPTION (documented `PARITY-EXCEPTION:`)

✅ **In parity (field-by-field notes):**

- **SKU default:** unspecified spec materializes `"Standard"` on both engines (Pulumi `locals.go` switch default; Terraform `locals.tf` ternary fallback)
- **True-default optional bools** (`public_network_access_enabled`, `export_policy_enabled`): Pulumi presence-guards the proto `optional` and falls back to `true`; Terraform uses `optional(bool, true)` — identical deploy for an absent value
- **`retention_policy_in_days`:** unset omits the argument on both engines (Azure keeps untagged manifests forever); a value — including 0 — turns the policy on
- **`network_rule_bypass_option`:** only an explicit choice is sent on both sides (Pulumi empty-string guard, Terraform `null`), so unspecified defers to Azure's `AzureServices` default identically
- **`network_rule_set`:** both map DENY→`Deny` else `Allow`, and both hard-set the per-rule action to `Allow` (ARM supports nothing else)
- **`georeplications`:** both produce alphabetical location order (Pulumi sorts explicitly; Terraform's location-keyed `for_each` map iterates in key order) — keeping manifests order-insensitive against azurerm's ordering quirk; per-replication `zone_redundancy_enabled`, `regional_endpoint_enabled`, and `tags` all pass through on both sides
- **`identity`:** identical enum→ARM string mapping including the comma-separated `"SystemAssigned, UserAssigned"`; `identity_ids` resolve `StringValueOrRef` to plain ARM IDs on both sides
- **`encryption`:** both pass `identity_client_id` + `key_vault_key_id` (resolved values) only when the block is set
- **Feature-gated outputs:** `system_assigned_identity_principal_id` is empty-string when no system identity exists on both sides (Terraform `try(..., "")`, Pulumi nil-guarded `ApplyT`); admin credentials and `data_endpoint_host_names` are provider-computed identically

🔵 **Documented exception:**

- **Tag shape** — Pulumi emits `resource_kind` as the lowered `CloudResourceKind` enum string and omits `resource_id` when `metadata.id` is empty; Terraform emits the family-wide snake-case literal (`azure_container_registry`) and falls back to `metadata.name` for `resource_id`. A `PARITY-EXCEPTION:` comment is present in BOTH modules (`iac/pulumi/module/locals.go`, `iac/tf/locals.tf`), the divergence is output-neutral (tags never feed stack outputs), and aligning the shapes is a family-wide convention change, not a per-kind fix. Per the audit rule, this is NOT a defect.
