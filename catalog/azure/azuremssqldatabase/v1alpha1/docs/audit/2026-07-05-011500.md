## Category 5b: Cross-Engine IaC Parity (the gate this audit leads with)

Field-by-field sweep of `iac/tf/` vs `iac/pulumi/module/` against
`spec.proto` + `stack_outputs.proto`:

- **Resource surface identical**: one `azurerm_mssql_database` /
  `mssql.Database` — ARM's TDE, short/long-term retention, and
  threat-detection sub-APIs are argument blocks inside the single
  resource on both engines.
- **Enum vocabularies exhaustive and identical**: all eight create modes,
  secondary types, license types, enclave types (incl. ARM's explicit
  `Default`), the four backup-redundancy values (wire
  `Geo`/`GeoZone`/`Local`/`Zone`), import credential/auth kinds, and
  Defender states.
- **Conditional-send behavior identical**: unspecified create_mode and
  sku_name not sent (Azure computes its serverless default); every
  optional dial forwarded only when present; collation/TDE-enabled/
  geo-backup presence-guarded to their documented defaults; unset LTR
  horizons omitted (ARM's `PT0S` semantics).
- **The email_account_admins bool→string mapping identical**: both
  engines render `Enabled`/`Disabled` for this resource's wire contract
  (which differs from the server-scope policy's bool).
- **Outputs identical**: `database_id`, `database_name`.
- **Documented PARITY-EXCEPTION (pre-existing, family-wide)**: the tag
  metadata shape; output-neutral, recorded in both modules.

**Verdict: PARITY ✅ — no undocumented divergence.**
