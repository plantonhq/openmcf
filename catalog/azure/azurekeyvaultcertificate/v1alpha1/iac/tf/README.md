# AzureKeyVaultCertificate Terraform Module

## Overview

This Terraform module provisions an X.509 certificate inside an Azure Key
Vault using the `azurerm` provider. It creates a single
`azurerm_key_vault_certificate` -- a DATA-PLANE object: the provider talks
to the vault's `{name}.vault.azure.net` endpoint, not ARM, so the deploying
credential needs certificate permissions on the vault ("Key Vault
Administrator" or "Key Vault Certificates Officer" RBAC role, or
certificate permissions in a legacy access policy) even if it owns the
subscription.

The certificate can be GENERATED by the vault (self-signed or CA-issued,
from `certificate_policy`) or IMPORTED from an existing PFX/PEM bundle
(`certificate`) -- or both, when an import carries an explicit governing
policy. Enrollment against issuer "Self" completes synchronously; a CA
issuer keeps the operation pending until the CA responds.

## Resources Created

- `azurerm_key_vault_certificate.main` -- the certificate with its three
  faces (certificate, private key, secret bundle)

## Variables

| Variable | Type | Description |
|----------|------|-------------|
| `metadata` | object | Planton metadata (name, org, env) |
| `spec` | object | Certificate specification |

Key spec fields:

| Field | Required | Description |
|-------|----------|-------------|
| `name` | yes | 1-127 letters/digits/hyphens, unique among the vault's certificates; ForceNew |
| `key_vault_id` | yes | The vault's ARM ID (resolved from an AzureKeyVault reference); ForceNew |
| `certificate` | one of | Import: base64 `contents` + optional `password` (both sensitive -- the bundle carries the private key); changing contents imports a new VERSION |
| `certificate_policy` | one of | Generate/govern: `issuer_name` ("Self"/"Unknown"/CA issuer name), `key_properties`, `lifetime_actions` (enum names mapped through exhaustive vocabularies in locals), `secret_properties.content_type` (PKCS12/PEM → media types), `x509_certificate_properties` |
| `tags` | no | User tags, merged over metadata-derived tags (user wins) |

Everything in the policy except `lifetime_actions` creates a new
certificate version when changed; lifetime actions update in place.

## Outputs

| Output | Description |
|--------|-------------|
| `certificate_id` / `versionless_id` | Data-plane IDs (versioned / renewal-following) |
| `secret_id` / `versionless_secret_id` | The secret face -- what TLS terminators consume |
| `certificate_name` / `version` | Name and current version |
| `thumbprint` | SHA-1 fingerprint |
| `resource_manager_id` / `resource_manager_versionless_id` | ARM (control-plane) IDs |

## Operational Notes

- A deleted certificate's name stays reserved in the vault for the
  soft-delete retention window; the provider's default features purge
  soft-deleted certificates on destroy so the name frees up immediately.
- Renewals mint a new version (fresh private key unless
  `reuse_key = true`); consumers on the versionless references follow
  automatically.
