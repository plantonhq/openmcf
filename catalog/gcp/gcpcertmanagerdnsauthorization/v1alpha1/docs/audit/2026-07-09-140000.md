## Detailed Findings

### Protobuf API Definitions — validation quality note

**New forged kind** (enum 716, `gcpcmda`) — extracted from hidden inline
authorizations on the legacy cert spec into a first-class composable resource.
The spec models one Certificate Manager DNS authorization: ambient-optional
`project_id` ref, optional `authorization_name` (RFC CEL), required bare
`domain` (covers domain + wildcard, no `*.` prefix / trailing dot), optional
`description`, immutable `location` (defaults `global`), immutable `type`
(FIXED_RECORD / PER_PROJECT_RECORD), and user `labels`. Exports validation
record fields for `GcpDnsRecord` composition. 10-case spec test.

**Session deliverables:** full kind forge (proto, stubs, BUILD, registry
entry at 716); dual-engine `dns_authorization.go` / TF modules; two presets
(standard-domain, shared-per-project); `cert_manager_dns_authorization.go`
verifier (domain + validation-record match); E2E `minimal` leaf scenario;
`GcpCertManagerCert` prerequisite wiring updated to reference this kind.

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- Both engines map `google_certificate_manager_dns_authorization` with
  identical domain, location, type, description, and labels merge (user
  first, platform `planton-ai_*` wins).
- `authorization_name` defaults to `metadata.name` on both engines when omitted.
- Outputs export `authorization_id` (full resource name), `domain`,
  `dns_record_name`, `dns_record_type`, `dns_record_data` — the composition
  triple `GcpDnsRecord` consumes. Verifier confirms live validation record
  matches exported fields.

### Composition contract

Leaf kind — no registry prerequisites. Upstream of `GcpCertManagerCert`
(registry lists this as a prerequisite). One authorization per distinct
domain; reuse across certificates covering that domain or its wildcard.
Lifecycle independent of certificates — survives rotation. Three-node flow:
**this kind** → `GcpDnsRecord` → `GcpCertManagerCert`.
