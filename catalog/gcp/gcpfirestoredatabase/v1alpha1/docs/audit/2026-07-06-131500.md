## Detailed Findings

### 1–2. Registry and Structure

✅ Enum 632; full anatomy including a new `e2e/` (minimal scenario with
`${E2E_RUN_ID}`-scoped database name — deleted database names are
reserved through a retention window — plus the published
`prerequisite.yaml` the index/backup-schedule chains install).

### 3. Protobuf API Definitions

✅ Spec at the released 6.50.0 floor. The rebuild added
`app_engine_integration_mode` (ENABLED/DISABLED, immutable, Datastore
Mode legacy integration) and extended outputs extend-only:
`version_retention_period`, `key_prefix`, `update_time`. Existing
surfaces held: type (Native XOR Datastore Mode), location, PITR,
delete_protection_state (optional default DISABLED), STANDARD/ENTERPRISE
edition with the ENTERPRISE⇒Native CEL, CMEK → GcpKmsKey. Recorded
skips (released-schema-probe verified): the three ENTERPRISE access
modes + `user_creds` (absent from released 6.50.0), resource tags,
`firestore_document` (app data), `firestore_field` TTL overrides
(data-lifecycle policy; on concrete pull). Composite indexes and backup
schedules are first-class sibling kinds, not exclusions. 50-case spec
test green.

### 4–5. IaC Modules

✅ Both engines: Firestore API enablement (new — was absent);
`deletion_policy` hardcoded DELETE identically (the provider default
ABANDON would leak databases on destroy); canonical Pulumi.yaml (stale
`binary:` gone); `~> 6.0`. No labels surface on the resource — documented
identically.
