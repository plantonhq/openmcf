## The change

`spec.push_config.push_endpoint` is now a `StringValueOrRef` with
`default_kind = GcpCloudRun` and
`default_kind_field_path = "status.outputs.url"` (was a plain `string`).
Rationale: pushing to a Cloud Run service in the same environment is the
canonical serverless consumer pattern, and a Cloud Run URL contains a
generated suffix that exists only after the service deploys — so a plain
string could neither reference it nor be assembled from parameters. The
required constraint is preserved; the field remains an HTTPS endpoint and
accepts any literal URL exactly as before.

## Cross-engine parity — PARITY ✅

- **Terraform:** zero functional change. The proto→tfvars converter flattens
  `StringValueOrRef` to a plain string; `variables.tf` already typed the
  field `string` and `main.tf` consumes it unchanged. Verified end to end
  with a real-converter `planton tofu plan` on a push manifest — the plan
  renders `push_config { push_endpoint = ... oidc_token { ... } }` exactly.
- **Pulumi:** one line — the module reads `GetValue()` on the resolved
  reference, the same pattern the sibling `oidc_token.service_account_email`
  field already uses.
- Stack outputs unchanged; `pkg/outputs` conformance green;
  `validate-outputs` green on both module dirs.
