## Detailed Findings

### Protobuf API Definitions — validation quality note

The spec models the Layer-0 GCP project container: required immutable
`project_id` (6–30 char CEL, globally unique, 30-day reservation caveat
documented), optional `display_name`, `parent_type` + numeric `parent_id`,
`billing_account_id` (billing-format pattern), user `labels`, create-time-only
`tags` (ForceNew), `auto_create_network` defaulting **false** (secure
hardening — explicit `GcpVpcNetwork` is the composable path), `enabled_apis`
(`.googleapis.com` pattern), and three-way `deletion_policy`
(DELETE/PREVENT/ABANDON). IAM grants deliberately excluded — model as
`GcpProjectIamMember`. Registry marks `container_kind: true`. 18-case spec
test.

**Session deliverables:** spec rebuild with honest deletion semantics and
default-network suppression; dual-engine `project.go` / `apis.go` (API
enablement) / TF modules; `project.go` verifier (ACTIVE lifecycle +
`planton-ai_resource` label; absence accepts DELETE_REQUESTED); two presets
(standard-production, development); E2E profile set to **plan-only** (tier 2).

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- Both engines map `google_project` + `google_project_service` (per
  `enabled_apis`) with identical project_id, display_name, parent, billing,
  labels merge, auto_create_network, and deletion_policy.
- Create-time `tags` map identically (ForceNew on both engines).
- Outputs: `project_id`, `project_number`, `name`, `billing_account`,
  `labels` — resolved from the created project on both engines.
- API enablement: `disable_on_destroy=false`, `disable_dependent_services=true`
  on both engines.

### Composition contract

Root container kind — every other GCP kind's ambient `project_id` ref wires
to `status.outputs.project_id` via `default_kind: GcpProject`. No registry
prerequisites. IAM is composable via `GcpProjectIamMember`. Deleted project
IDs reserve for ~30 days (documented on `project_id`).

### Recorded skips (with reasons)

  creation is conditional on credentials the shared `planton-e2e` run does not
  carry. Offline converter plans + verifier contract are the validated path.
- `tags` post-create mutation — ForceNew by design; runtime tag binding is
  out-of-band (documented).
- Billing-account linkage live assertion — requires `roles/billing.user` on a
  real billing account; pattern validated offline.
