## Detailed Findings

### 1–2. Registry and Structure

✅ Enum 642 (first free data-sub-band slot after the Spanner backup
schedule); `id_prefix: gcpbttbl` unique; `prerequisites:
[GcpBigtableInstance]` drive the E2E chain. Full anatomy.

### 3. Protobuf API Definitions

✅ The table as a first-class many-per-instance node: instance ref → the
instance's `instance_name` output, `table_name` → `metadata.name`
fallback, column families with aggregate `type` shortcuts
(intsum/intmin/intmax/inthll documented), **per-family GC policy folded
in** (max_age/max_versions/mode/raw `gc_rules` JSON under
mutual-exclusion CEL — the provider's one-per-family
`google_bigtable_gc_policy` resource has no independent life, so it
fails the split test and folds), `split_keys` (ForceNew — replacing the
table, documented), `change_stream_retention` (1–7 days),
`automated_backup_policy` (retention + frequency), `row_key_schema`
(provider's no-in-place-update caveat recorded), `deletion_protection`
string default PROTECTED — the API-side guard, stronger than an IaC-side
one for a data-bearing resource, explicit on both engines. Recorded
skips: authorized/logical/materialized views + schema bundle (Tier-2
kinds on concrete pull), IAM trio (catalog-wide additive-only stance).
32-case spec test green.

### 4–5. IaC Modules

✅ Both engines: Bigtable Admin API enablement; table + one GC-policy
resource per declaring family (TF `for_each` keyed by family / Pulumi
loop with per-family resource names); `ignore_warnings` for
replicated-instance GC expansion. Canonical Pulumi.yaml; `~> 6.0`.
