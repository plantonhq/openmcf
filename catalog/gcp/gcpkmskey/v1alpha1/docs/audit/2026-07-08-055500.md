### Protobuf API Definitions — validation quality note

The spec stands at the released 6.50.0 floor (verified against a released-provider schema dump, not the clone's main): 10 fields covering the full modeled surface — ring ref, name, purpose, rotation, destroy window, version template (all four protection levels), skip-initial-version, `import_only`, ref-shaped `crypto_key_backend` (un-defaulted, awaiting the EKM kind), and user `labels`. Three message-level CEL rules move the API's create-time rejections to pre-deploy: rotation⇔ENCRYPT_DECRYPT, import_only⇒skip_initial_version_creation, crypto_key_backend⇔EXTERNAL_VPC. The rotation CEL enforces the provider's own validator exactly (≥ 86400s, ≤ 9 fractional digits); `purpose` and `algorithm` are deliberately free strings mirroring the provider contract (GCP adds values over time — a hardcoded allowlist is a staleness trap; the previous allowlist was removed on those grounds). The undeletable/version-centric lifecycle is taught throughout. 43-case spec test.

**Parity verdict: PARITY ✅**

- Both engines enable `cloudkms.googleapis.com` on the ring's project (extracted from the ring path identically), `disable_on_destroy=false`.
- **The former live label-parity break is CLOSED**: TF previously stamped ZERO labels while Pulumi stamped `planton-ai_*`. Both engines now merge user labels beneath the identical `planton-ai_*` attribution set, same merge order — and the E2E verifier asserts the `planton-ai_resource` label live, making the regression permanently guarded.

- **Bridged-provider `deletion_policy` neutralized**: the pinned pulumi-gcp line carries a client-side `deletion_policy` absent from the released Terraform GA resource. The bridged-only `key_access_justifications_policy` is not sent by either engine (recorded skip).
- Outputs resolved from the created resource on both engines: `key_id`, `key_name`, plus extend-only `primary_version_name`/`primary_state` with identical empty-string semantics for keys without a primary (TF `try()` guards ↔ Pulumi length-guarded `ApplyT`).
- Zero PARITY-EXCEPTION comments needed (the deletion_policy pin is a neutralization to identical behavior, documented in-module).
