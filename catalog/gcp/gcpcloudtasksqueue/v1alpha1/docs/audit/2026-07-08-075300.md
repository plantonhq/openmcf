### Protobuf API Definitions — validation quality note

The spec stands at the released 6.50.0 floor (verified against the provider's
`v6.50.0` git tag and a released-provider schema probe): project (ambient),
queue name (deliberately required — deleted queue IDs are reserved by the API
for up to 7 days, so the name deserves an explicit choice, never a derived
default), location, the full queue-level `http_target` surface (method,
header overrides, OAuth-XOR-OIDC tokens as GcpServiceAccount refs, flattened
`uri_override`), `app_engine_routing_override`, rate limits, retry config,
and logging sampling. CEL moves the API's create-time rejections pre-deploy:
OAuth/OIDC mutual exclusion, method/scheme/enforce-mode vocabularies,
sampling-ratio bounds. The provider's nested single-field wrapper blocks
(`path_override.path`, `query_override.query_params`, `header.{key,value}`)
are flattened with the mapping documented. 46-case spec test.

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- Both engines enable `cloudtasks.googleapis.com` (`disable_on_destroy=false`)
  and honor the ambient-project contract (empty `project_id` → provider
  default project) identically.
- Optional-field folding identical: empty strings → null/omitted so API
  defaults apply; rate/retry dials use zero as the not-set sentinel (with
  `max_attempts = -1` preserved as the legitimate unlimited value);
  `sampling_ratio` 0.0 flows as a real value on both engines.
- The nested `path_override`/`query_override` blocks are only sent when set
  on both engines — live-verified no perpetual diff on the 6.x line (second
  plan after a real apply with both overrides set is empty).
- **Bridged-provider flags neutralized**: the pinned pulumi-gcp line carries
  a client-side `deletion_policy` and the 7.x-only `desired_state`/`state`
  surface, both absent from released 6.50.0. The Pulumi module pins
  `deletion_policy` to `DELETE` and deliberately does not use
  `desired_state`/`state`, each with a PARITY comment — no engine can accept
  intent the other silently drops.
- Outputs resolved from the created resource on both engines: `queue_id`,
  `queue_name`, and `max_burst_size` (the GCP-computed burst ceiling; TF
  reads `rate_limits[0].max_burst_size`, Pulumi `RateLimits.MaxBurstSize()`).
  The E2E verifier cross-checks the output against the live API value, so an
  engine exporting a stale or fabricated value fails live.
- Neither kind supports GCP labels (API limitation) — documented identically
  in both modules; no label computation exists on either engine.
- Zero PARITY-EXCEPTION comments needed (the bridged-flag pins are
  neutralizations to identical behavior, documented in-module).

### Recorded skips (with reasons)

- `desired_state` (pause/resume) + the `state` attribute — added to the
  provider in 7.0.0; absent from released 6.50.0 (tag-verified), so modeling
  them would make the Terraform engine silently drop user intent. Pause/
  resume is a runtime operation (`gcloud tasks queues pause|resume`).
  Returns when the catalog moves to the 7.x major.
- `deletion_policy` — client-side, absent from released 6.50.0; bridged flag
  pinned for parity (above).
- `max_burst_size` as an input — Computed-only in the provider; exported as
  an output instead.
- Per-queue IAM member/binding/policy trio — resource-scoped IAM glue kinds
  are deliberately not modeled; grant `roles/cloudtasks.enqueuer` via
  GcpProjectIamMember.
