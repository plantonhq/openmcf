### Protobuf API Definitions — validation quality note

The spec stands at the released 6.50.0 `google_workbench_instance` floor:
24 contiguous fields. The depth rebuild added user `labels` (closing the
recurring TF zero-labels live parity class), `confidential_instance_config`
(AMD SEV), `reservation_affinity` (all three consume types, key/values
coherence CEL for RESERVATION_SPECIFIC), `enable_managed_euc`,
`enable_third_party_identity`, the external-IP `access_configs` arm, and
`desired_state` (ACTIVE/STOPPED CEL, declarative stop/start) — every
addition verified GA on the released line AND expressible in the bridged
pulumi-gcp SDK before modeling (guarding the one-engine class). The
singular `boot_disk`/`data_disk`/`accelerator_config`/`network_interface`/
`service_account` sub-messages are provider-authentic (the released schema
caps each at one), so inbound reference shapes stay stable. CEL covers
zone-shaped `location`, disk types/bounds, accelerator enum, vm⇔container
image exclusivity, and external-IP⇔disable_public_ip coherence. 56-case
spec test.

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- Both engines enable `notebooks.googleapis.com` + `compute.googleapis.com`
  (`disable_on_destroy=false`) and gate the instance on both.
- Identical labels merge: user labels first, `planton-ai_*` attribution set
  wins on conflict; asserted live by the verifier (`planton-ai_resource`).
- **Shielded-VM false-value semantics unified**: the API enables vTPM and
  integrity monitoring by default, so an explicit `false` actively disables
  them. Both engines now omit false flags (TF `? true : null`, Pulumi
  omit-when-false) — server defaults stay intact for unset flags, and the
  same manifest realizes the same posture on either engine.
- Optional sub-messages folded identically: unset messages omitted entirely
  on both engines; empty strings → null so provider defaults apply.
- Bridged-provider `deletion_policy` (absent from the released 6.x line;
  first shipped in provider v7.33.0) pinned to `DELETE` on Pulumi with a
  PARITY comment.
- Outputs resolved from the created resource on both engines with identical
  keys: `instance_id`, `instance_name`, `proxy_uri`, `state`, `creator`,
  `create_time`, plus extend-only `health_state`/`update_time`.

### VM image guidance — live-corrected staleness

The live run surfaced that GCP has retired the legacy deep-learning-VM
notebook image families (`common-cpu-notebooks`, `tf-latest-gpu` no longer
resolve in `deeplearning-platform-release`). The spec comments, presets,
hack manifest, catalog page, and E2E scenario were all corrected to the
maintained surface: omit `vmImage` for the service default (latest
Workbench image — the recommended shape, immune to family retirement), or
pin `cloud-notebooks-managed` / `workbench-instances` explicitly.
