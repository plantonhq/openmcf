# HA

This preset runs the Planton operator with two leader-elected replicas
and raised resource headroom — for clusters where several platforms ride
one operator and reconcile latency after a node failure matters.

## When to Use

- Clusters running multiple KubernetesPlantonPlatform declarations
  (per-team platforms on one shared cluster)
- Production clusters where the operator's node dying should not pause
  platform reconciliation for a reschedule

## Key Configuration Choices

- **`replicas: 2` + leader election** — the standby holds no work but
  takes the lease within seconds of the leader dying; this shortens
  OPERATOR failover, it never adds reconciliation throughput
- **Raised resources** — a manager watching several platforms carries
  more informer state than the chart's single-platform defaults assume
- Everything else matches the standard preset — one operator per
  cluster (self-enforced), chart-owned definitions kept on uninstall

## Placeholders to Replace

None — this preset deploys as-is.
