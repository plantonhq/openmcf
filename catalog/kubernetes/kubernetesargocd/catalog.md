# Argo CD

Deploy [Argo CD](https://argo-cd.readthedocs.io) — the declarative GitOps continuous-delivery engine for Kubernetes — from the official `argo-cd` Helm chart. Argo CD watches Git repositories and keeps cluster state converged with what the repositories declare; this component installs and shapes the control plane itself at chart grain: every Argo CD component individually sized, the Redis cache as an explicit three-way choice, SSO and RBAC as first-class blocks, and an honest first-login story.

The grain is deliberate: **this kind deploys the control plane; declaring what it deploys is not its job.** Once Argo CD runs, Applications, AppProjects and ApplicationSets are plain custom resources — declare them via KubernetesManifest, a chart, or Argo CD's own UI/CLI. Exposure is composed too: the server stays ClusterIP, and KubernetesIngress or Gateway kinds publish it over the exported `server_service` handle.

## What Gets Created

When you deploy this Cloud Resource, the IaC module provisions:

- **Helm release** (official `argo-cd` chart, default pin `10.2.1`, named `metadata.name`) — the API/UI **server**, the **application controller** (the reconciliation engine), the **repo server** (clones repositories and renders manifests — the first component to saturate as syncs grow), the **ApplicationSet controller**, and three toggleable components with different chart defaults: **notifications** (on), **dex** (on — inert until connectors are declared), and the **commit server** (off — only hydrated-manifest workflows need it)
- **A Redis cache** matching the declared arm — the chart's single-pod bundled cache when nothing is declared, a 3-node Sentinel HA cluster behind HAProxy, or no Redis at all when an external endpoint is referenced. Whatever the arm: Redis here is a **disposable cache** — losing it costs a re-sync, never state; everything real lives in the CRs and Git history
- **The Argo CD CRDs** (Application, AppProject, ApplicationSet) — installed and kept on uninstall by default; see the one-way door below
- **Kubernetes Namespace** — created only when `create_namespace` is true; otherwise the namespace must already exist
- **The `argocd-initial-admin-secret` Secret** — generated by Argo CD itself at first start with the admin password (when the local admin is enabled); its name and a ready-made port-forward command land in the stack outputs

## Before You Deploy

### Planton Setup

- **Kubernetes Provider Connection** — an active connection in the Connect module with credentials for the target cluster.

### Cluster Side

- **Cluster-scoped permissions** — Argo CD manages applications across namespaces; the install creates CRDs, ClusterRoles and ClusterRoleBindings.
- **metrics-server** — only if you enable autoscaling on the server or repo server (the HPAs meter CPU requests).
- **At least three schedulable worker nodes** — only for the HA Redis arm; its pods carry a required anti-affinity and stay Pending on smaller clusters.
- **kube-prometheus-stack** — only if you set `service_monitors_enabled` (the ServiceMonitor objects need the Prometheus Operator CRDs to admit).

## Deploy

### Console

Open the deployment store, find **Argo CD on Kubernetes**, and click **Deploy**. The creation wizard walks you through namespace placement, the chart pin, access (the local admin tri-state and the public domain), each component at chart grain, the Redis three-arm choice, SSO, RBAC, repositories, the CRD lifecycle (with the one-way-door warning), metrics, the air-gap image path, placement, and the Helm-values escape hatch. Start from the **Dev GitOps** preset in the [Presets](#presets) tab.

### CLI

```yaml
apiVersion: kubernetes.planton.dev/v1
kind: KubernetesArgocd
metadata:
  name: dev-argocd
  org: acme-corp
  env: dev
spec:
  namespace:
    value: dev-argocd
  create_namespace: true
```

```shell
planton apply -f argocd.yaml
```

This near-empty spec is a complete GitOps control plane at chart defaults. First login: read the generated password from the `argocd-initial-admin-secret` Secret (the exact name and a `kubectl port-forward` command are in the stack outputs), sign in as `admin`, and point your first Application at a repository.

### InfraChart

Compose Argo CD behind its namespace with a reference, and the InfraPipeline orders the deploys:

```yaml
spec:
  namespace:
    valueFrom:
      kind: KubernetesNamespace
      name: gitops-namespace
      fieldPath: spec.name
  create_namespace: false
```

## Key Configuration

**The first-login story is honest.** With the local admin enabled (the default), Argo CD generates the admin password once per install into the fixed-name `argocd-initial-admin-secret` Secret — one generated-password install per namespace. Rotation is change-then-delete: change the password via the CLI, then delete the Secret. `admin_enabled` is a genuine tri-state: unset defers to the chart (admin on), explicit `false` retires the local admin — **only after SSO works**, or the UI locks everyone out.

**TLS terminates at the composed edge.** The server ships a self-signed listener — fine for a port-forwarded dev loop. When real exposure is composed (KubernetesIngress or a Gateway kind over the exported `server_service`), set `server.insecure: true` so the edge terminates TLS; leaving the self-signed listener behind a proxy double-encrypts and breaks gRPC CLI traffic. Set `domain` at the same time — SSO redirect URLs and CLI login hints embed it.

**Components scale for different reasons.** The repo server saturates first — every sync clones and renders there; scale it (replicas or an autoscaler) when sync latency grows. Controller replicas are **shards across target clusters**, not load-balanced copies — sharding a single-cluster install buys nothing. Server and repo server both take an optional autoscaling block (min/max default 1/5, max ≥ min enforced); a CPU HPA without a CPU request never scales.

**The Redis choice is a three-arm decision.** Declare nothing and the chart runs its single-pod bundled cache — right for dev and small installs. The `ha` arm runs a 3-node Sentinel cluster (replicas ≥ 3; remember the anti-affinity needs three nodes). The `external` arm points at an endpoint you operate — its `host` composes by reference from a KubernetesValkey's exported service; optional credentials ride a named Secret, never the manifest.

**SSO is direct OIDC, dex connectors, or deliberately both.** The `oidc` block does provider-native OIDC: name, issuer, client ID, and the client secret as a **name + key reference** to an existing Secret — the credential never rides the manifest, and the referenced Secret must carry the `app.kubernetes.io/part-of: argocd` label or Argo CD refuses to read it (compose it from KubernetesSecret or KubernetesExternalSecret). Leave the reference empty for a public-client PKCE flow. `dex_config` carries dex connector YAML for protocols OIDC alone cannot speak (SAML, LDAP, GitHub teams) — it requires the dex component enabled, and its secrets use Argo CD's `$<secret-name>:<key>` indirection, never inline. Configuring both puts two SSO buttons on the login screen — legitimate during a migration, a misconfiguration otherwise.

**RBAC defaults to invisible.** An empty `policy_default` means authenticated users see nothing until a `policy_csv` rule grants access — the safe default for a shared instance; `role:readonly` is the friendlier alternative. `scopes` defaults to `[groups]`, mapping the identity provider's group claims into policy subjects. `exec_enabled` opens an interactive shell into live containers through the API server — a deliberate grant paired with an RBAC `exec` rule, never a default.

**Repositories here are public/anonymous only.** The `repositories` repeater registers public Git/Helm sources. Credentialed repositories are composed as labeled Secrets (`argocd.argoproj.io/secret-type: repository`) next to the install — credentials never transport through this spec.

**THE CRD ONE-WAY DOOR:** `crds.keep` defaults to `true` for a reason — flipping it to `false` means uninstalling this release **deletes every Application, AppProject and ApplicationSet in the cluster**, not just the control plane. And the ownership trap on `crds.install`: CRDs installed by one release cannot be adopted by a second — a reinstall that skips them must set `install: false` or the upgrade collides.

**`reconciliation_timeout`** controls how often Argo CD polls repositories (chart default `180s`; empty defers). Lower means faster syncs but more repo-server and Git load; webhook-driven setups can raise it instead.

**`helm_values` merges last** — the escape hatch for chart surface beyond the typed fields (notification templates and triggers, per-component env, ingress annotations the chart renders itself). Anything here silently overrides the typed fields on every deploy; never put secrets in it.

**Air-gap path:** the `image` block re-points repository/tag/pull-secret for the Argo CD image that serves all core components; dex and the bundled Redis pull their own chart-default images — re-point those via `helm_values` when mirroring everything.

## Outputs and Dependencies

### What This Component Consumes

| Field | References | Purpose |
|-------|-----------|---------|
| `spec.namespace` | KubernetesNamespace (`spec.name`) | Where Argo CD runs |
| `spec.redis.external.host` | KubernetesValkey (`status.outputs.service`) | The external Redis/Valkey endpoint |
| `spec.sso.oidc.client_secret_secret` | Existing Secret (name + key, labeled `app.kubernetes.io/part-of: argocd`) | The OIDC client secret |
| `spec.redis.external.credentials_secret_name` | Existing Secret | External Redis auth |
| `spec.image.pull_secret_name` | Existing Secret | Air-gap/private-mirror image pulls |

### What This Component Provides

After provisioning, `status.outputs` contains values that downstream Cloud Resources can consume via ValueFromRef:

| Output | Description | Common Downstream Use |
|--------|-------------|----------------------|
| `namespace` | Namespace Argo CD runs in | Composing labeled Secrets (OIDC, repositories) next to the install |
| `release_name` | Helm release name (= metadata.name) | Operational tooling |
| `server_service` | The API/UI server Service name | Ingress/Gateway exposure |
| `server_kube_endpoint` | Cluster-internal FQDN of the server | In-cluster API clients |
| `initial_admin_secret_name` | The generated-password Secret (`argocd-initial-admin-secret`) | The first login: `kubectl get secret … -o jsonpath='{.data.password}' \| base64 -d` |
| `port_forward_command` | Copy-paste `kubectl port-forward` for the server | Local access before exposure is composed |

## Common Patterns

Browse the [Presets](#presets) tab for ready-to-deploy configurations.

| Preset | Posture | What it carries |
|--------|---------|-----------------|
| **Dev GitOps** | dev loop / first contact | The smallest useful Argo CD: chart defaults end to end, first login through the generated-password Secret and the exported port-forward command |
| **Team SSO + RBAC** | a team's shared instance | Direct OIDC with the client secret as a labeled-Secret reference, read-only-by-default RBAC with a platform admin group, TLS handed to the composed edge, and the local admin retired (`admin_enabled: false`) once SSO carries the load |
| **Scaled Platform** | hundreds of Applications | Server and repo server on HPAs with explicit CPU requests, a memory-sized controller, the HA Sentinel Redis arm, faster reconciliation, and ServiceMonitors for the monitoring stack |

## Works With

- **Kubernetes Namespace** — referenced placement; the InfraPipeline orders namespace-first.
- **Kubernetes Ingress / Gateway API kinds** — expose the UI/API over the exported `server_service` handle (set `server.insecure` and `domain` when composing).
- **Kubernetes Valkey** — the external Redis arm references its exported service endpoint.
- **Kubernetes Secret / Kubernetes External Secret** — compose the labeled OIDC client-secret Secret and credentialed-repository Secrets next to the install.
- **Kubernetes kube-prometheus-stack** — scrapes the per-component ServiceMonitors when `service_monitors_enabled` is set.
- **Kubernetes Manifest** — declare Applications/AppProjects/ApplicationSets once the control plane runs.
