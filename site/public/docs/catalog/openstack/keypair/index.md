# OpenStack Keypair

Deploys a Nova compute keypair on OpenStack -- an SSH key used for authenticating access to compute instances. The keypair supports both importing an existing public key and generating a new keypair, with the public key fingerprint and name captured in outputs for downstream instance references.

## What Gets Created

When you deploy this Cloud Resource, the IaC module provisions:

- **Compute Keypair** -- an SSH keypair registered in Nova, either imported from a provided public key or generated by OpenStack with the private key available as a one-time sensitive IaC output

## Before You Deploy

### OpenStack Account

- **Compute access** -- the OpenStack credentials must have permissions to create keypairs in the Nova API. Standard `member` role access on the target project is sufficient.
- **Public key** (recommended) -- for production use, generate a keypair locally with `ssh-keygen` and provide the public key in the spec. This keeps the private key off the IaC state file and under your control.
- **Generated keypair** (alternative) -- if `publicKey` is omitted, OpenStack generates a new keypair. The private key is stored in IaC state as a sensitive value and must be retrieved immediately after creation via `pulumi stack output private_key --show-secrets` or `terraform output -raw private_key`. It is not included in platform stack outputs.

## Deploy

### Console

Open the deployment store, find **OpenStack Keypair**, and click **Deploy**. The creation wizard walks you through preset selection, environment and connection configuration, and spec fields. Start from the **Import Public Key** preset in the [Presets](#presets) tab to pre-populate a working configuration.

### CLI

Create a manifest and apply it:

```yaml
apiVersion: openstack.planton.dev/v1
kind: OpenStackKeypair
metadata:
  name: admin-key
  org: acme-corp
  env: prod
spec:
  publicKey: "ssh-rsa AAAAB3NzaC1yc2EAAAA... user@host"
```

```shell
planton apply -f keypair.yaml
```

This imports an existing SSH public key into OpenStack. The private key never leaves your machine or enters the IaC state. Instances referencing this keypair by name will inject the public key for SSH authentication.

## Key Configuration

These are the most important decisions when configuring a keypair. Explore the full field reference in the [API Explorer](#api-explorer) tab.

**Import vs generate** -- `publicKey` controls the keypair mode. When provided, the given public key is imported (recommended for production). When omitted, OpenStack generates a new keypair and the private key is available only as a sensitive IaC-level output. Import mode avoids storing private key material in IaC state.

**Region override** -- `region` overrides the region from the provider configuration. Most deployments leave this empty to use the provider default. Set it only when targeting a specific Nova region in a multi-region deployment.

## Outputs and Dependencies

### What This Component Consumes

This component has no foreign key dependencies.

### What This Component Provides

After provisioning, `status.outputs` contains values that downstream Cloud Resources can consume via ValueFromRef:

| Output | Description | Common Downstream Use |
|--------|-------------|----------------------|
| `name` | Name of the keypair in Nova | Instance `keyPair` field for SSH authentication |
| `fingerprint` | MD5 fingerprint of the SSH public key | Key verification, audit trails |
| `public_key` | SSH public key in OpenSSH format | Configuration management, authorized_keys distribution |
| `region` | OpenStack region where the keypair was created | Region-aware downstream resources |

## Common Patterns

Browse the [Presets](#presets) tab for ready-to-deploy configurations.

**Import existing public key** -- Imports a locally generated SSH public key into OpenStack. The private key stays on your machine or in your secret manager. This is the recommended approach for production environments where key management is handled externally. Start from the **Import Public Key** preset.
