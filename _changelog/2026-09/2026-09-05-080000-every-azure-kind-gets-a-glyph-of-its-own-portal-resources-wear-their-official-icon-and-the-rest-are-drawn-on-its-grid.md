# Every Azure kind gets a glyph of its own: the services and portal resources Microsoft draws wear their official icon, and the rest are drawn flat on Azure's own grid

## What changed

- **All 185 Azure logos are judged under the logo law.** Before, one Key Vault icon (Microsoft's `Icon-security-245`, a key in a ring) was worn as a placeholder by 49 kinds -- every Cosmos DB kind, every Data Factory kind, Application Insights, the storage account, the Service Bus topic, the Redis linked server -- a networking icon by 15 more (function apps, the load balancer, the NSG, the public IP), a DNS icon by the 13 Front Door and DNS kinds, a container icon by nine Container Apps kinds; 100 kinds shared a glyph in all, 184 named no provenance, and a dozen hand-made files imitated the official gradient style for VPN, Virtual WAN, Traffic Manager, and WAF kinds. Now no two Azure kinds share a drawing, every file opens with its provenance, and every official file comes from the current package.
- **A kind that IS an Azure service or a portal resource Microsoft draws wears its official icon** -- 87 of them from `Azure_Public_Service_Icons_V24`, which Microsoft permits "in architectural diagrams, training materials, or documentation." Microsoft's set draws most portal resources, not only services, so the officials reach deep: the virtual network AND its subnet, NSG, application security group, route table, network interface, public IP and prefix, IP group, NAT gateway, load balancer, application gateway, private endpoint and link service, peering, virtual network gateway and its connection, local network gateway, ExpressRoute circuit and Direct port, Virtual WAN and its hub, Traffic Manager profile, DNS zone, private DNS resolver, Front Door profile, firewall and its policy, WAF policy, bastion; the VM, scale set, availability set, compute gallery and image definition, disk, snapshot, and disk encryption set; AKS, container apps and their environment, container instances, the registry; App Service, Functions, the plan; Cosmos DB, DocumentDB (the vCore Mongo cluster's new name), SQL server, database, and elastic pool, MySQL and PostgreSQL flexible servers, Redis and Managed Redis, the storage account and its container, queue, share, and table, Data Factory; Machine Learning; Event Hubs and their clusters, Event Grid topics, domains, and system topics, Service Bus; Key Vault and its keys, managed identities; Application Insights and its web test, Log Analytics, alerts, autoscale, diagnostic settings, data collection rules; resource groups, Recovery Services vaults, Backup vaults, resource guards; AI Foundry and its projects, AI Services, AI Search.
- **The gate caught Microsoft sharing a drawing with itself.** Event Grid Domains and Event Grid Subscriptions ship as one picture; the domain keeps it and the subscription is drawn (events from a topic delivered to one handler). Recorded in rule 021 as the shape the gate exists for.
- **Everything else is Planton-drawn on Azure's 18 grid, flat** -- 97 kinds in Azure blue (`#0078d4`) with cyan (`#50e6ff`) as the one accent and white for cut-outs, no gradients, so a drawing never passes for an official file but reads as its kin. The vocabulary: a Cosmos DB database a globe-ringed cylinder, its container a partitioned box of items, the Mongo database a cylinder of pages and its collection a stack of documents in a box, a role definition a sheet of allowed actions and a role assignment a person badge on the sheet; an event hub one partitioned pipe, a consumer group readers tapping the pipe, an authorization rule a key over the pipe (over a queue for Service Bus), a geo-disaster recovery pair two namespaces with a failover arrow, a schema group a brace pair in a box; a Service Bus queue messages lined up, a topic one publisher fanning out, a subscription one endpoint fed from a topic; a Key Vault secret a locked sheet and a certificate a sealed sheet; a federated identity credential an external token at an identity door; the Front Door endpoint a globe with a door, a custom domain a name tag on the door, an origin a server behind it, an origin group servers bracketed, a route a path from the door, a rule set a sheet at the door, a security policy a shield on a domain, the WAF policy a shield with a brick wall; a VPN site a branch building with its tunnel endpoint, a point-to-site gateway tunnels to individual clients, a hub connection a cable into the hub; every Machine Learning child on the model spark (an online endpoint answering a request, a deployment a version behind it, a batch endpoint over a queue of inputs, a compute cluster a rack, an instance one notebook machine); every Data Factory child on the factory's pipeline (activities chained, a dataset a table pointed at, a linked service a cable to a store, a data flow transforms branching and merging, an integration runtime a gear on compute, a trigger a clock firing a pipeline); backup policies a schedule sheet over the thing protected and protected items the thing under the vault shield; an action group one alert fanning out to receivers; a scheduled query alert a bell on a query line.
- **Azure joins the judged-provider pin.** `judgedProviders` is `gcp, cloudflare, kubernetes, auth0, openfga, aws, azure`; its 284 baseline entries are gone (184 provenance, 100 shared) and nothing else in the baseline moved. Copying the Key Vault icon back onto the Cosmos DB account under its own `<desc>` fails the gate and the pin at both kinds by name.

## Why

An Azure chart in a Planton console said "Key Vault" on a Cosmos DB account, a storage account, a Data Factory pipeline, and forty-six other things. Microsoft publishes a set that draws nearly every portal resource and permits it for exactly this use, so the icon an Azure engineer already knows is available for 87 kinds unaltered, and the other 97 are drawn in the same two colors on the same grid so the sheet reads as one provider.

## How to check

```bash
go test ./pkg/cataloglogo/ ./pkg/anatomy/                 # green, Azure absent from the baseline and pinned
grep -L '<desc>' catalog/azure/*/logo.svg                 # prints nothing
go run ./tools/catalog-logo-sheet/ -provider azure        # then open the HTML it names
```
