## Apply-Time Validator Source-Diff

Read `firewall_resource.go` (schema lines 38-234 +
`resourceFirewallCreateUpdate` 236-405 + delete 493-592) and
`validate/` helpers:

- **NO CustomizeDiff exists.** The provider's imperative apply-time
  checks, all front-loaded as CELs:
  - `validateFirewallIPConfigurationSettings` (exactly one subnet_id
    across ip_configuration blocks) → `exactly_one_subnet_bearing_ip_configuration`.
  - The management-vs-data name-collision check →
    `management_name_distinct_from_ip_configurations`.
- **Provider-documented create contract** ("A public ip address is
  required unless a management_ip_configuration block is specified",
  verbatim in the provider's schema note) →
  `public_ip_required_without_management_path`.
- **Structural ARM pairing** (hub sku ⇔ virtual_hub; hub firewalls carry
  no ip_configurations; VNet firewalls need one) → three CELs, justified
  by the deployment models' disjoint addressing (visible in the
  provider's own AZFW_Hub fixtures).
- **Subnet name validators** (`AzureFirewallSubnet` /
  `AzureFirewallManagementSubnet`, plan-time on the resolved ID): live on
  the FK docs + the E2E fixture; unreachable at authoring time on an
  unresolved reference -- the provider still enforces post-resolution.
- **Documented, NOT CEL'd** (not in the provider source): BASIC tier
  requiring the management configuration (Azure-documented,
  ARM-enforced); tier pairing with the policy (cross-resource).
- **Live-E2E-caught contract added post-audit (seventh CEL)**: ARM
  rejects firewall-level DNS parameters on a policy-attached firewall
  (`AzureFirewallDNSConfigNotAllowedForVhubOrVnetWithPolicy` -- absent
  from the provider source, caught by the first live Pulumi lane).
  Front-loaded as `policy_owns_dns_configuration` with both error paths
  spec-tested; scenario, hack manifest, and docs corrected. Both engines
  were behaviorally identical before and after (the payload was wrong
  identically -- a spec-level contract gap, not a parity gap).
- **DNS wire encoding**: servers imply EnableProxy=true in
  AdditionalProperties -- coupling documented on the spec; both modules
  pass the flags verbatim.
- **Rule-collection preservation on update** (the classic-collections
  coexistence hook): irrelevant here by design -- the classic trio is a
  recorded skip and the modules never touch rule collections.
