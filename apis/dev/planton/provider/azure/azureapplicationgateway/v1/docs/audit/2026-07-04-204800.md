## Category 5b: Cross-Engine IaC Parity (the gate this audit leads with)

Field-by-field sweep of `iac/tf/` vs `iac/pulumi/module/` against
`spec.proto` + `stack_outputs.proto`:

- **Resource surface identical**: one atomic
  `azurerm_application_gateway` / `network.ApplicationGateway` carrying
  all 20+ sub-object families; no side resources on either engine.
- **The derived gateway IP configuration is byte-identical**
  (`{name}-gateway-ip` from the single dedicated-subnet FK) so both
  engines converge on the same ARM object.
- **Enum vocabularies exhaustive and identical**: SKU (name+tier from
  one value), the shared protocol vocabulary (Http/Https/Tcp/Tls) with
  layer restrictions enforced at the spec, rule types, IP allocations,
  identity types, SSL policy types, TLS versions (TLSv1_0-TLSv1_3),
  redirect types, URL components (path_only/query_string_only), and the
  9 custom-error status codes.
- **Boolean-behind-a-string identical**:
  `cookie_based_affinity_enabled` maps to ARM's Enabled/Disabled on both
  engines.
- **Presence-guard sweep clean**: request_timeout (30), L4
  timeout_in_seconds (30), http2 (false) fall back explicitly on the
  Pulumi side where Terraform's `optional(...)` defaults apply;
  optional strings forwarded only when non-empty on both.
- **Map outputs identical**: `backend_address_pool_ids` and
  `frontend_ip_configuration_ids` keyed by sub-object NAME on both
  engines (Terraform comprehensions over the resource's computed
  blocks; Pulumi ApplyT over the same computed arrays — the
  load-balancer precedent), plus the private-frontend address pair.
- **Documented exception (family-wide, output-neutral)**: the
  metadata-derived tag shape carries the standing `PARITY-EXCEPTION`
  comment in BOTH modules.

## Recorded Skips (verified deliberate, documented in docs/README.md)

- `authentication_certificate` (v1-SKU-only backend auth; v1 SKUs are
  retired at plan time in azurerm 4.x).
- `http_listener.host_name` singular (subsumed by `host_names`).
- `backend_http_settings.sni_name`/`sni_validation_enabled`/
  `certificate_chain_validation_enabled` — azurerm 4.80 fields ABSENT
  from pulumi-azure v6.38 (the latest); a one-engine-only input would
  ship a silent-drop divergence (the `release_policy` precedent).
- A second `gateway_ip_configuration` (subnet-migration maneuver, not
  steady state).
- Computed `private_endpoint_connection` and
  `ssl_certificate.public_cert_data` conveniences.

## E2E Exclusions (recorded)

The Key-Vault-TLS arm (`ssl_certificates[].key_vault_secret_id`) is
proven offline (plan + spec tests): a live run would add a vault +
certificate + identity + grant fixture chain (~25 extra minutes) to a
seam whose resolution mechanics (StringValueOrRef → versionless secret
id) are identical to the WAF-policy FK proven live.
