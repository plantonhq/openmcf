### 3. Protobuf API Definitions (22.20%)

✅ The spec covers the complete `azurerm_linux_function_app` argument surface (azurerm v4.80):

- **All three storage bindings**: account name + access key, account name + managed identity, and the NEW `storage_key_vault_secret_id` (Key Vault secret URL format CEL) — with the provider's ExactlyOneOf and key-XOR-identity contracts as message CELs.
- `function_app_name` (globally unique), plan FK, `functions_extension_version`, the NEW `daily_memory_time_quota` (the Consumption cost circuit breaker), `enabled`, `builtin_logging_enabled`, `content_share_force_disabled`.
- The NEW blocks shared with the Web App surface: `sticky_settings`, `backup` (+ schedule), `auth_settings_v2` (full Easy Auth v2 with all nine provider blocks), basic-auth publishing toggles, `zip_deploy_file`, `vnet_image_pull_enabled`, `virtual_network_backup_restore_enabled`, user `tags`.
- site_config: function application stack (dotnet + isolated toggle, node, python, java, powershell, nested docker, custom runtime), the serverless dials (`app_scale_limit`, `elastic_instance_minimum`, `pre_warmed_instance_count`, `runtime_scale_monitoring_enabled`), the NEW `api_management_api_id`/`api_definition_url`/`managed_pipeline_mode`/`remote_debugging_enabled`/`minimum_tls_cipher_suite`/`health_check_eviction_time_in_min`, TLS floors as enums, both IP-restriction surfaces, `app_service_logs`, ACR managed-identity pulls, `application_insights_key` (now `sensitive`, matching the provider).
- FK straggler fixed: `storage_mounts[].access_key` now carries `default_kind` → `AzureStorageAccount.primary_access_key` AND the `sensitive` annotation (both previously missing — the Web App twin had them).
- Closed vocabularies converged to enums (client-cert mode, TLS, FTPS, load balancing, pipeline mode, IP actions, connection-string types, storage-mount types, identity types, backup units, auth vocabularies).
- Spec test: 52 Ginkgo cases (every CEL error path), `go test` green.

**Recorded skips (in `docs/README.md`):** Flex Consumption — Azure's own SEPARATE resource type (`azurerm_function_app_flex_consumption`, FC1 plans, container-endpoint storage, top-level runtime) — recorded as a standalone-kind candidate, not folded into this spec; legacy `auth_settings` v1; deployment slots; Windows variant.
