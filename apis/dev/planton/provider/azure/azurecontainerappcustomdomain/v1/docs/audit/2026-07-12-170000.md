## Apply-Time Validator Source-Diff

Read `container_app_custom_domain_resource.go` (plain resource, schema
+ Create/Read/Delete) and the provider docs page:

- **RequiredWith certificate-id -> binding-type** (schema-level), and
  the create path forces `BindingType = Disabled` when no certificate
  is supplied -- front-loaded as the bidirectional pairing CEL
  (together for BYO, both absent for managed; a binding type without a
  certificate would be silently overridden to Disabled by the provider,
  which the CEL turns into an instant message instead).
- **Create requires ingress** ("app has no Ingress configuration for
  Custom Domains") -- a cross-resource contract; documented on the spec
  and taught by the app fixture's ingress-enabled shape.
- **The asuid TXT validation** is enforced BY AZURE during the polled
  create (the provider performs no DNS pre-check) -- documented, with
  the DNS-first sequence on every user-facing artifact.
- **The ignore-changes doctrine**: the provider docs mandate
  `ignore_changes = [certificate_binding_type,
  container_app_environment_certificate_id]` for the managed flow
  (Azure mutates both asynchronously). Applied EXACTLY per flow -- the
  managed TF variant and the Pulumi managed branch carry it; the BYO
  side deliberately does not (an unconditional ignore would swallow a
  user's legitimate certificate change -- the silent-data-loss class).
- **Read tolerates both certificate ID shapes** (`certificates/` and
  `managedCertificates/`), routing the managed one into the computed
  attribute both modules export as `managed_certificate_id`.
- All arguments ForceNew; no Update func; no CustomizeDiff.
