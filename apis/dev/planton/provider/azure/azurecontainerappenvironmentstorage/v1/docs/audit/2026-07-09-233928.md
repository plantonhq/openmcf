## Schema Coverage vs azurerm v4.80 (`container_app_environment_storage_resource.go`)

All seven provider fields modeled: environment FK, name (as `storage_name`,
the provider's `ManagedEnvironmentStorageName` contract as a CEL),
`share_name` (FK → `AzureStorageShare.share_name`), `access_mode` (closed
enum ReadOnly/ReadWrite), `account_name` (FK →
`AzureStorageAccount.storage_account_name`), `access_key` (sensitive, FK →
`primary_access_key` -- the established key seam), `nfs_server_url`. The
update semantics (only access_key updates in place) are documented on the
spec and both modules.

## Apply-Time Validator Source-Diff

The provider's `RequiredWith` (account_name ↔ access_key) and `ConflictsWith`
(account_name ⊥ nfs_server_url) schema contracts are front-loaded as one
SMB-XOR-NFS message CEL. NFS-requires-VNet-injection stays apply-time (a
cross-resource contract; documented).

## Composability

fields FK-default to this kind's `storage_name` output, making share-backed
volumes fully reference-driven (account → share → registration → volume).

protocol handling identical (SMB pair or NFS URL, never both).
