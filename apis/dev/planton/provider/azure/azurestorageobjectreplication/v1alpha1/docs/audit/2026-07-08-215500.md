### 5c. Apply-Time Validator Source-Diff (per the audit rule)

Walked `storage_object_replication_resource.go` Create/Update/Read/Delete
beyond the schema:

- **The two-sided create protocol** (destination first — Azure assigns the
  policy GUID and rule IDs there — then the source with the returned rules)
  is provider logic both engines share under the bridge; the kind models the
  pair as one resource, matching.
- **`ObjectReplicationCopyBlobsCreatedAfter`** (OnlyNewObjects / Everything /
  RFC 3339) → mirrored exactly as the CEL.
- **The Everything/OnlyNewObjects ↔ ARM sentinel translation**
  (`1601-01-01T00:00:00Z` / empty) lives in the provider's expand/flatten —
  shared by both engines, so no spec involvement.
- **Container-name validation** (`validate.StorageContainerName`) applies to
  the rule names — they arrive as references here, so the container KIND's
  own CEL guards the name at its source; a literal bypassing it still hits
  the provider's validator. No invented rule.
- **The versioning/change-feed prerequisites are ARM-side** (no provider
  validator — the API rejects) → cross-resource, documented on the spec,
  modules, presets, and exercised by the E2E fixtures.
- No CustomizeDiff on this resource.
