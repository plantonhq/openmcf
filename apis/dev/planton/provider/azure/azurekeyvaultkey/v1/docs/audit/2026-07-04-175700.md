## Category 5b: Cross-Engine IaC Parity (the gate this audit leads with)

Field-by-field sweep of `iac/tf/` vs `iac/pulumi/module/` against
`spec.proto` + `stack_outputs.proto`:

- **Resource surface identical**: one `azurerm_key_vault_key` /
  `keyvault.Key` with the rotation policy riding the resource on both
  engines.
- **Enum vocabularies exhaustive and identical**: key types (RSA /
  `RSA-HSM` / EC / `EC-HSM` — hyphenated on the wire), curves (`P-256`,
  `P-256K`, `P-384`, `P-521`), operations (camelCase `unwrapKey` /
  `wrapKey` / ...); both engines carry the complete maps so a missing
  entry cannot silently drop a capability.
- **Unset-side behavior identical**: `key_size` nil for EC keys, `curve`
  nil/omitted for RSA keys (spec CELs enforce the pairing up front); an
  unset curve lets Azure default to P-256 on both engines.
- **Rotation policy identical**: `expire_after`/`notify_before_expiry`
  pass through as ISO 8601 durations; the `automatic` block's two
  triggers presence-guarded identically.
- **Outputs identical**: `key_id`, `versionless_id`, `key_name`,
  `version`, `resource_id`, `resource_versionless_id`, `public_key_pem`,
  `public_key_openssh` — confirmed populated 8/8 live on both engines.
- **Documented exception (family-wide, output-neutral)**: the
  metadata-derived tag shape carries the standing `PARITY-EXCEPTION`
  comment in BOTH modules.

## Notes

- **Recorded skip — `release_policy`** (secure key release): the latest
  pulumi-azure v6 SDK carries no `releasePolicy` on `keyvault.Key`, so
  modeling it would create a one-engine-only input and break the
  100%-parity invariant. Recorded in `docs/README.md` with the enabler
  (pulumi-azure gaining the field). The surface is confidential-computing
  niche (HSM-only).
- Retrofits shipped with this forge: `AzureContainerRegistry`
  `encryption.key_vault_key_id` now defaults to this kind's
  `versionless_id` output (rotation propagates); `AzureAksCluster` KMS
  `key_vault_key_id` converted from a plain string to a `StringValueOrRef`
  defaulting to the versioned `key_id` output (AKS pins key versions by
  design — the deliberate contrast is documented in both specs).
- The E2E verifier rides the key's read-only ARM proxy
  (`Microsoft.KeyVault/vaults/keys`) via the established generic GetByID
  pattern — zero new SDK dependencies for this kind.
