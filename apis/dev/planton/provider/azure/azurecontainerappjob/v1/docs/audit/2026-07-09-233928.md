## Schema Coverage vs azurerm v4.80 (`container_app_job_resource.go` + `helpers/container_app_job.go`)

The full surface is modeled: name (as `job_name`, mirroring the provider's
no-dots job-name contract), location (jobs carry their own, unlike apps),
resource group FK, environment FK, `replica_timeout_in_seconds` (required),
`replica_retry_limit`, workload profile, the job template (containers, init
containers, volumes -- no scale block, matching `JobTemplateSchema`), the
three trigger configs with the provider's `ExactlyOneOf` as a message CEL
(each ForceNew, each with parallelism/replica_completion_count defaults 1/1),
the event trigger's scale contract (max/min executions, polling, KEDA rules
reusing `CustomScaleRuleSchema` -- including `identity_id` and the KEDA
allowlist CEL), secrets, registries, identity, and tags. Computed
`outbound_ip_addresses` + `event_stream_endpoint` export as outputs.

## Apply-Time Validator Source-Diff

1. `ExactlyOneOf` across the trigger blocks -- front-loaded
   (`job_exactly_one_trigger`).
2. Event scale rules validate `custom_rule_type` against the provider's KEDA
   allowlist (the rules reuse the app's custom-scale-rule schema) --
   front-loaded with the identical 58-value vocabulary (fixed in this audit
   cycle: the field was an open string; a CEL + error-path test were added).
3. Probe per-type contracts -- the same container-level CELs as the app kind.
4. Volume storage_name pairing -- the same CEL as the app kind.

## Parity

Both engines: shared Pulumi builder, empty TF provider block, identical wire
maps and value-or-default handling for trigger parallelism, completion counts,
and event-scale dials. Only the family-wide tag-shape PARITY-EXCEPTION
(output-neutral, documented).
