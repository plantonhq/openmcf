✅ **In parity:**

- All 34 spec fields are honored by both engines with identical ARM values, including the create-option source fields (`source_resource_id`, `source_uri` + `storage_account_id`, `image_reference_id` / `gallery_image_reference_id`, `upload_size_bytes`), the PremiumV2/Ultra performance dials (`disk_iops_*` / `disk_mbps_*`, `logical_sector_size`), the shared-disk seam (`max_shares` + read-only budgets), encryption (`disk_encryption_set_id` / `secure_vm_disk_encryption_set_id` / `security_type` / `trusted_launch_enabled`), and network posture (`network_access_policy` / `disk_access_id` / `public_network_access_enabled`).
- Optional-enum handling is behaviorally identical: unspecified enums send nothing on both engines so Azure's defaults apply (Pulumi empty-string guard ↔ Terraform null ternary).
- Zero-default bools (`on_demand_bursting_enabled`, `optimized_frequent_attach_enabled`, `performance_plus_enabled`, `trusted_launch_enabled`) resolve to the provider's `false` default on both sides — Terraform sends an explicit `false`, Pulumi sends `false` (or omits `trusted_launch_enabled` when false, where the provider default is also `false`). Deployed outcome identical.
- Both output sets flatten onto the same three `AzureManagedDiskStackOutputs` fields.

🔵 **Documented exception:**

- **Tag shape (family-wide).** Terraform emits the snake-case `resource_kind = "azure_managed_disk"` literal and falls back `resource_id → metadata.name`; Pulumi emits the lowered `CloudResourceKind` enum string and omits `resource_id` when `metadata.id` is empty. A `PARITY-EXCEPTION:` comment is present in **both** modules (`iac/tf/locals.tf` and `iac/pulumi/module/locals.go`), the divergence is output-neutral (tags never feed stack outputs), and it is flagged as a family-wide convention change rather than a per-kind fix. This is the known documented item and is NOT a defect.
