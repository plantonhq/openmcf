### 5c. Apply-Time Validator Source-Diff (per the audit rule)

Walked `storage_account_local_user_resource.go` Create/Update/Read/
CustomizeDiff beyond the schema:

- **Create sanity check** `SshKeyEnabled != (len(keys) != 0)` errors both
  directions → mirrored as the keys-pair-with-key-auth message CEL.
- **Schema `AtLeastOneOf`** on the two auth flags → mirrored as the
  at-least-one-method message CEL.
- **CustomizeDiff**: flipping `ssh_password_enabled` marks `password`
  recomputed — i.e. the password REGENERATES on false→true → documented on
  the spec field and both modules (behavioral note, not a validation).
- **Update path regenerates the password when enabling password auth**
  (the provider's own comment records that Azure requires it) → covered by
  the same documentation.
- **`computevalidate.SSHKey`** parses the key material; the spec's CEL is a
  format mirror (type prefix + base64 body) — stricter than nothing, looser
  than a full parse; the provider still parses at plan/apply. Recorded in
  docs/README.md.
- Nothing else: the permission letters are assembled provider-side from the
  booleans (`expandPermissionScopes`), which the spec models directly.
