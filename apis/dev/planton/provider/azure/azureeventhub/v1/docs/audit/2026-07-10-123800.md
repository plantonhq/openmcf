## Apply-Time Validator Source-Diff

Read `eventhub_resource.go` Create/Update + CustomizeDiff + validators:

- **partition_count can never decrease** (Update body): a state
  transition -- documented on the field, not CEL-able.
- **partition_count change requires Premium or a dedicated cluster**
  (Update body fetches the parent namespace): cross-resource -- documented
  on the field and in docs/README.md.
- **partition/retention tier caps** (ValidateEventHubPartitionCount /
  ValidateEventHubMessageRetentionCount admit the DEDICATED ceilings;
  the real cap depends on the parent's tier): the spec admits 1-1024 and
  1-90 exactly as the provider's validators do, with the per-tier caps
  documented as Azure's apply-time contract -- a stricter CEL would
  invent a rule the provider does not enforce.
- **message_retention XOR retention_description** (ExactlyOneOf):
  front-loaded as the `event_hub_retention_exactly_one_model` CEL.
- **retention window pairing** (expand sends only the policy-matched
  field; the mismatched one is silently dropped): front-loaded as the
  `event_hub_retention_matches_cleanup_policy` CEL -- the anti-silent-drop
  treatment, stated in the message.
- **capture UserAssigned requires storage_authentication_id**
  (CustomizeDiff): front-loaded as the
  `event_hub_capture_identity_matches_auth_type` CEL; the
  absent-otherwise half prevents the provider's silent identity drop on
  the SAS path (expand sends no identity for StorageSAS).
- **archive_name_format all-nine-tokens** (ValidateEventHubArchiveNameFormat):
  front-loaded as a field CEL.
- **capture destination name single value** ("EventHubArchive.AzureBlockBlob"
  is the only accepted value): a one-value constant -- both modules send
  it unconditionally; recorded skip.
- No spec CEL invents a rule the provider and ARM do not enforce.
