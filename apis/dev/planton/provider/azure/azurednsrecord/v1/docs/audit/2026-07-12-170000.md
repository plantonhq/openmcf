# Audit Report: AzureDnsRecord

**Date:** 2026-07-12-170000
**Component:** AzureDnsRecord (enum 410, provider azure, id_prefix `azdrec`)
**Mode:** full audit with `--parity` focus (breaking rework)

## Summary

**Score: 100% -- Fully Complete. PARITY ✅ COVERAGE ✅**

Reworked from a flat value-list shape to nine typed payloads with an
exactly-one-of contract (no discriminator enum -- the payload IS the
type). The rework REMOVES a shipped misdeploy class: the previous
modules hardcoded SRV priority/weight/port (10/10/80), CAA flags/tag
(0/"issue"), and a single MX preference, silently ignoring the value
formats the spec documented -- every SRV/CAA record deployed wrong and
multi-preference MX was inexpressible. The typed shapes make those
fields user-declared and validated. Alias records
(`target_resource_id` on A/AAAA/CNAME -- azurerm's full alias surface)
and record-set tags are new coverage. Both engines migrated onto the
shared provider builder (the previous Pulumi module inlined
`azure.NewProvider`, silently breaking keyless OIDC auth).

## Apply-Time Validator Source-Diff

Read all nine `dns_*_record_resource.go` files (schema + create/update):

- **A/AAAA records-XOR-target**: the provider hand-rolls "one of either
  records or target_resource_id must be specified" in create/update
  (plus schema ConflictsWith); CNAME uses schema ExactlyOneOf.
  Front-loaded as per-payload XOR message CELs.
- **AAAA element validation** (`IsIPv6Address`) -- mirrored; the spec
  additionally validates A addresses as IPv4 (azurerm leaves A elements
  unvalidated and ARM rejects garbage at apply -- the asymmetry is not
  copied; this is format validation of the type's own value space, not
  an invented business rule).
- **CAA tag vocabulary** (`issue`/`issuewild`/`iodef`/`contactemail`,
  case-sensitive) -- the closed enum maps to exactly these wire values
  in both engines.
- **TXT value 1-4096** with the provider's transparent 254-char
  chunking on expand -- mirrored as items string bounds; the chunking
  documented (read-side rejoin keeps state stable).
- **MX preference is string-typed in the provider** (parsed as int) --
  the spec models the integer; both engines convert.
- No CustomizeDiff on any record resource. azurerm's MX-only optional
  `name` defaulting to `@` is provider ergonomics -- the spec requires
  `name` uniformly (documented).
- No spec CEL invents a rule the provider/ARM does not enforce; ranges
  (0-65535, 0-255) are the RFC value spaces ARM enforces.
