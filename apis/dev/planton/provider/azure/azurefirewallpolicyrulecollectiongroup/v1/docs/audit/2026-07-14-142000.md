## Apply-Time Validator Source-Diff

Read `firewall_policy_rule_collection_group_resource.go` (1015 lines,
schema + expand/flatten paths) and the shared name validator:

- **The ONLY imperative validation is the NAT translated-target XOR**
  (`expandFirewallPolicyRuleNat`): both-set and neither-set each error at
  apply time. Front-loaded as the `nat_translated_target_exactly_one`
  message CEL with both error paths spec-tested.
- **NAT protocols TCP/UDP only** (schema StringInSlice): the shared
  protocol enum + the `nat_protocols_tcp_udp_only` CEL.
- **NAT destination_ports MaxItems 1** (1-64000, no wildcard): mirrored
  as `max_items: 1`; the value grammar (port/range, bounds) is left to
  the provider's plan-time `PortOrPortRangeWithin`, documented.
- **Priorities** IntBetween(100, 65000) on group and collections:
  mirrored exactly.
- **Application protocol port** IntBetween(0, 64000): mirrored.
- **NAT collection action**: the schema literal "Dnat" is the only legal
  value -- modeled as a constant both engines send unconditionally
  (recorded skip + re-enable trigger in research docs).
- Deliberately NOT front-loaded (ARM-side, absent from the provider):
  at-least-one source / at-least-one destination per rule; Premium
  gating of destination_urls / web_categories / terminate_tls; FQDN
  rules requiring DNS proxy. All documented on the spec fields instead
  -- no invented CELs.
