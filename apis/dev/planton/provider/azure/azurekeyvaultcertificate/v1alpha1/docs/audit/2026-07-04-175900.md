## Category 5b: Cross-Engine IaC Parity (the gate this audit leads with)

Field-by-field sweep of `iac/tf/` vs `iac/pulumi/module/` against
`spec.proto` + `stack_outputs.proto`:

- **Resource surface identical**: one `azurerm_key_vault_certificate` /
  `keyvault.Certificate` carrying the import block and/or the policy
  block, matching the spec's at-least-one contract.
- **Enum vocabularies exhaustive and identical across the THREE casings
  Azure is sensitive about**: UpperCamel action types (`AutoRenew` /
  `EmailContacts`), lowerCamel key usages (`digitalSignature`,
  `keyEncipherment`, ...9 values), hyphenated/lowercase key types
  (`RSA-HSM`, `oct`), curves, and the content-type media strings
  (`application/x-pkcs12` / `application/x-pem-file`).
- **Unset-side behavior identical**: EC certificates omit `key_size` so
  Azure derives it from the curve; imports omit the x509 block; empty
  `extended_key_usage` renders as unset on both engines (TF `optional([],)`
  and azurerm's empty-list normalization vs Pulumi's skip-when-empty —
  same ARM payload).
- **Sensitive handling identical**: `certificate.contents` and
  `certificate.password` flow to the engines' sensitive inputs; neither
  engine echoes them in outputs.
- **Outputs identical**: `certificate_id`, `versionless_id`, `secret_id`,
  `versionless_secret_id`, `certificate_name`, `version`, `thumbprint`,
  `resource_manager_id`, `resource_manager_versionless_id` — confirmed
  populated 9/9 live on both engines.
- **Documented exception (family-wide, output-neutral)**: the
  metadata-derived tag shape carries the standing `PARITY-EXCEPTION`
  comment in BOTH modules.

**Verdict: PARITY ✅ — no undocumented divergence.**

## Notes

- The lifetime-action trigger is an exactly-one CEL
  (days_before_expiry XOR lifetime_percentage) — Azure's certificate
  API accepts one trigger per action; the spec catches at validation time
  what azurerm defers to deploy time.
- Retrofit shipped with this forge: `AzureApplicationGateway`
  `ssl_certificates[].key_vault_secret_id` converted from a plain string
  to a `StringValueOrRef` defaulting to this kind's
  `versionless_secret_id` output — the gateway follows certificate
  renewals automatically.
- The E2E verifier is data-plane (`azcertificates`) by necessity: ARM
  exposes no certificate read proxy (azurerm synthesizes the
  resource-manager id client-side). The verifier runs under the test
  subscription's Key Vault data-plane bootstrap grant.
- Recorded skips in `docs/README.md`: the vault-wide certificate-contacts
  resource and the CA-issuer configuration resource (adoption backlog;
  `issuer_name` composes with issuers by name once demanded).
