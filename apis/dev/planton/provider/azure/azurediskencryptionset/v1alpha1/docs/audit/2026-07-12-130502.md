## Apply-Time Validator Source-Diff

Read `disk_encryption_set_resource.go` schema + CustomizeDiff + create:

- **key URL versioning vs rotation** (`ValidateNestedItemID` admits any
  version-type; ARM enforces versionless-iff-rotation at apply): NOT
  CEL-able -- a field CEL cannot dereference a `StringValueOrRef`'s
  resolved value. Documented in the spec comment and BOTH modules; the FK
  default points at `versionless_id` so the recommended posture is the
  default path.
- **encryption_type vocabulary** (StringInSlice of three): closed enum;
  the irregular `ConfidentialVm` (not `ConfidentialVM`) wire casing
  verified against the vendored SDK constants and identical in both
  engines' maps (the vendor-constant-casing class).
- **identity UAI→SystemAssigned is ForceNew** (`ForceNewIfChange`
  CustomizeDiff): a state transition -- documented on the identity type
  field, not CEL-able.
- **identity_ids iff user-assigned flavor** (commonschema identity
  contract): front-loaded as the `des_identity_ids_match_type` CEL.
- **federated_client_id IsUUID**: front-loaded as a field CEL.
- **name contract** (`DiskEncryptionSetName` regex): documented on the
  field (1-80, no leading underscore, no trailing hyphen/period); the
  min/max bounds are validated, the full regex is ARM's own apply
  surface.
- No spec CEL invents a rule the provider and ARM do not enforce.

## Recorded Skips

- `managed_hsm_key_id` -- azurerm 4.x's deprecated alias (removed in
  v5.0; ExactlyOneOf with key_vault_key_id). Keys backed by Azure Key
  Vault Managed HSM (a separate premium service, not modeled in the
  catalog) are out of scope; recorded on the key field's spec comment.
  Re-enable trigger: a Managed HSM kind entering the catalog.

  a knob.
