## Post-Review Addendum (2026-07-07, same session)

A deep review against the azurerm v4.80 source found two spec-level
defects the initial audit missed; both were fixed and the offline gate
re-run (spec tests, Bazel Pulumi build, full `planton tofu plan` on the
hack manifest):

1. **Indexing-policy contracts added as validation rules**: azurerm's
   `ValidateAzureRmCosmosDbIndexingPolicy` rejects at apply (a) a
   NONE-mode policy that declares included/excluded paths, and (b) any
   declared path set whose root path "/*" is missing from both lists or
   present in both. Both contracts are now message-level CEL rules on
   the indexing policy, with error-path tests, so the failure surfaces
   at validation instead of apply.
2. **Invented MULTI_HASH path-count minimum removed**: the old rule
   required more than one path for MULTI_HASH; neither azurerm's schema
   nor ARM enforces that (a single-level hierarchy is legal). The rule
   now enforces only ARM's real contracts: MULTI_HASH requires partition
   key version 2, and HASH takes exactly one path.

The score and both gates remain 100% / PARITY ✅ / COVERAGE ✅ with these
fixes applied and re-verified.
