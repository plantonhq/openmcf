## Category 5b: Cross-Engine IaC Parity (the gate this audit leads with)

Field-by-field sweep of `iac/tf/` vs `iac/pulumi/module/` against
`spec.proto` + `stack_outputs.proto`:

- **Resource surface identical**: one `azurerm_key_vault` /
  `keyvault.KeyVault`; no secret-creation resources on either engine (the
  legacy placeholder-secret paths are fully removed).
- **Tenant derivation identical**: both engines read the deploying
  credential's tenant from the client configuration (TF
  `azurerm_client_config`, Pulumi `core.GetClientConfig`); access-policy
  entries fall back to the same tenant.
- **Defaults materialize identically**: SKU unset → `standard` (both
  materialize; azurerm requires an explicit sku_name);
  `rbac_authorization_enabled` unset → true (TF `optional(bool, true)`,
  Pulumi presence guard); `public_network_access_enabled` unset → true;
  `soft_delete_retention_days` unset → 90; `purge_protection_enabled` /
  `enabled_for_*` plain bools pass through (Azure defaults false);
  network-ACL `bypass` unset → `AzureServices` (Azure's own default,
  materialized on both because azurerm requires a value in-block).
- **Enum vocabularies exhaustive on both engines**: SKU (2), default
  action (2), bypass (2), and the four permission sets (20 key / 8 secret
  / 16 certificate / 14 storage values) map the FULL proto value names to
  ARM's case-sensitive strings; a `tofu plan` carrying `PREMIUM`, `DENY`,
  `NONE`, and entries from every permission list renders the mapped values.
- **Outputs identical**: `key_vault_id`, `key_vault_name`, `vault_uri`,
  `tenant_id`, `resource_group_name` — byte-identical keys, confirmed
  populated 5/5 live on both engines.
- **Documented exception (family-wide, output-neutral)**: the
  metadata-derived tag shape (`resource_kind` casing + `resource_id`
  fallback) carries the standing `PARITY-EXCEPTION` comment in BOTH
  modules, matching the four session-008 kinds.

**Verdict: PARITY ✅ — no undocumented divergence.**

## Notes

- The rework removed the `secret_names` field and both engines'
  placeholder-secret creation (secret values are a secrets-management
  concern, never IaC state); outputs renamed to the kind-authentic
  `key_vault_id`/`key_vault_name` grain with the three FK consumers
  (VMSS ×2, AKS ×1) repointed and guarded by `validate-refs`.
- `purge_protection_enabled` now matches azurerm's real default (false);
  the prior invented always-true default is gone, and the production
  preset teaches enabling it.
- Recorded skips in `docs/README.md`: `contact` (v4 deprecated),
  certificate-contacts/issuer and managed-storage-account side-resources,
  and the standalone access-policy resource (folded inline).
