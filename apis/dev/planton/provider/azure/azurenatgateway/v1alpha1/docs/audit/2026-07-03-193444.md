## Critical Gaps

Blocking issues that prevent production readiness:

1. **Preset `01-standard.yaml` fails validation against the current spec**
   - **Why it blocks:** The preset is served on the catalog as the starting manifest. It uses
     the removed `subnetId` field, a field name that never existed (`idleTimeoutMinutes` vs the
     actual `idleTimeoutInMinutes`), and omits the now-required `name` field. Any user who
     deploys it hits three validation errors. The companion `.md` compounds it by documenting
     the removed `publicIpPrefixLength` knob.
   - **What to do:** Rewrite the preset pair for the current spec (region, `resourceGroup`
     value-wrapper, required `name`, optionally a `publicIpIds` reference) and consider a second
     preset showing the prefix-based egress-range pattern.
   - **Files:** `presets/01-standard.yaml`, `presets/01-standard.md`

2. **Undocumented parity divergence: unset `idle_timeout_in_minutes` handling (Pulumi)**
   - **Why it blocks:** See Category 5b below. Terraform encodes the module-level default
     (`optional(number, 4)`); Pulumi unconditionally sends `spec.GetIdleTimeoutInMinutes()`,
     which is `0` whenever the optional field is unset and the proto-default applier has not
     run. The azurerm-bridged provider validates `4-120`, so `0` fails the deploy loudly on
     any path that skips `protodefaults.ApplyDefaults` (per `pkg/iac/MODULE_PARITY.md`, the
     applier runs only in the CLI manifest loader). Not a silent misdeploy, but an
     engine-dependent failure mode.
   - **What to do:** In the Pulumi module, set `IdleTimeoutInMinutes` only when
     `spec.IdleTimeoutInMinutes != nil` (mirroring the module-level-default convention the
     `Auth0Client` precedent in `MODULE_PARITY.md` establishes), or default it to 4 in-module.
   - **File:** `iac/pulumi/module/main.go`

✅ **In parity:**

- Scope source, naming basis, SKU enum → ARM string mapping with omit-when-unspecified
  semantics (explicitly mirrored, with matching comments on both sides), zones omit-when-empty,
  per-entry IP and prefix association resources, tag merge order (metadata-derived first, user
  tags win), dependency ordering, and the full stack-output contract (automated guard passes).

⚠️ **Divergences (undocumented):**

- **`resource_id` tag fallback** — Terraform always emits the `resource_id` tag, falling back
  to `metadata.name` when `metadata.id` is empty (`locals.tf` `local.resource_id`); Pulumi
  emits the tag only when `metadata.id` is non-empty (`locals.go`). When the platform assigns
  an id (the normal case) the engines match; for id-less manifests (hack/CLI runs) the deployed
  tag sets differ. Impact: **cosmetic tag drift**. This same asymmetry exists across the Azure
  family (e.g. `azurepublicipprefix`), but it is undocumented here, so it counts.
  Fix: align Pulumi to the name-fallback (or Terraform to conditional emission) and/or add a
  `PARITY-EXCEPTION:` note in BOTH modules if the family-wide behavior is intended.
- **Unset `idle_timeout_in_minutes`** — Terraform: `optional(number, 4)` encodes the default at
  module level (matching the proto's `(options.default) = "4"` and the azurerm provider default).
  Pulumi: `pulumi.Int(int(spec.GetIdleTimeoutInMinutes()))` unconditionally, which sends `0`
  whenever the optional field is unset and `protodefaults.ApplyDefaults` has not run — the
  bridged provider's `IntBetween(4, 120)` validation then rejects the deploy. Impact:
  **engine-dependent loud failure on non-CLI input paths** (not a silent misdeploy). Fix: guard
  on field presence in the Pulumi module (the `Auth0Client` module-level-default precedent in
  `pkg/iac/MODULE_PARITY.md`).

**Effect on score:** caps Categories 4 & 5 at Partial (−1.00% Pulumi, −0.24% Terraform); the
idle-timeout divergence is additionally listed under Critical Gaps because it produces an
engine-dependent failure mode.
