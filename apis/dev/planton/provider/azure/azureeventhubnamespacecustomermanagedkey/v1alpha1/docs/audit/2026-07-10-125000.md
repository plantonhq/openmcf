## Apply-Time Validator Source-Diff

Read `eventhub_namespace_customer_managed_key_resource.go`:

- **The user-assigned identity must already be attached to the parent
  namespace** (Create/Update verify the UAI appears in the namespace's
  Identity.IdentityIds before calling ARM, with a helpful error):
  cross-resource -- documented on the field and in docs/README.md,
  deliberately not CEL'd (references cannot be dereferenced at
  validation time).
- **Delete is a NO-OP** (the provider logs and returns -- CMK cannot be
  removed once added): the add-only lifecycle, documented everywhere it
  matters; also why the kind has no E2E verifier registration
  (verify-absent after destroy is meaningless).
- **KeySource is a constant** (Microsoft.KeyVault, the only legal wire
  value): provider-internal, nothing to model.
- **The single-tenant capacity requirement** (dedicated cluster or
  PREMIUM) lives in ARM -- documented as the apply-time platform
  contract, not CEL'd (cross-resource).
- **Custom importer requires existing Encryption properties**:
  import-path behavior, no spec impact.
- No spec CEL invents a rule the provider does not enforce (the 1-10 key
  bound mirrors Azure's documented per-namespace key limit; azurerm
  validates each id's shape, front-loaded here by the vault-key FK
  default).
