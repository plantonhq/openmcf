## Apply-Time Validator Source-Diff

Read `container_app_environment_managed_certificate_resource.go`
(typed resource, schema + Create):

- **CertificateName validator** -- same contract as the BYO kind,
  front-loaded as the name CEL.
- **`domain_control_validation`** -- StringInSlice CNAME/HTTP, default
  HTTP; closed enum, both engines send the explicit HTTP fallback when
  unspecified.
- **Create BLOCKS on the LRO**
  (`ManagedCertificatesCreateOrUpdateCallbackThenPoll`, ~30-minute
  timeout): Azure only completes once domain validation succeeds, and
  the provider creates NO DNS records itself. Not front-loadable (the
  proof lives in public DNS) -- taught prominently on the spec header,
  both modules, README, catalog page, and presets.
- **Wildcard subjects**: Azure managed certificates cover exactly one
  concrete name; the provider leaves the rejection to the LRO (~30
  minutes in). The spec's subject CEL rejects wildcards up front --
  a mirror of Azure's own documented issuance rule, not an invention.
- Only tags update in place. No CustomizeDiff.
