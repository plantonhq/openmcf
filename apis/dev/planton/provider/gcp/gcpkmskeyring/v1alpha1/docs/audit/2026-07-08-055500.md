### Protobuf API Definitions — validation quality note

The released `google_kms_key_ring` resource has exactly three fields; this spec models 100% of that surface. `projectId` is an optional `StringValueOrRef` → `GcpProject` with the ambient-project fallback (both engines identically); `keyRingName` carries the API's `[a-zA-Z0-9_-]{1,63}` pattern; `location` is a required free string (regions, multi-regions, and `global` are all valid — no staleness-prone pattern). The undeletable lifecycle (no delete API, names permanently consumed, IAM-flows-down blast-radius guidance) is taught in the spec comments. 20-case spec test.

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- Both engines enable `cloudkms.googleapis.com` (`disable_dependent_services=true`, `disable_on_destroy=false`) and create the ring with name/location/project.
- Ambient project: TF folds empty → `null`; Pulumi omits `Project` when empty — identical provider-default resolution.
- No labels on either engine — the ring API has no labels surface (the Pulumi module's former dead label computation was removed).
- Outputs resolved from the created resource on both engines: `key_ring_id` (resource ID), `key_ring_name`, `location` (extend-only addition this rebuild).
- Destroy is state-only on both engines (GCP has no delete API for rings) — behavior identical by provider construction.
- Zero PARITY-EXCEPTION comments needed.
