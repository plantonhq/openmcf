## Spec depth vs the released provider floor

Modeled at the released `google ~> 6.0` floor of
`google_storage_bucket`: required globally-unique `bucket_name`
(explicit-name honesty for a global namespace), `location` (region /
dual-region / multi-region), ambient `project_id` (renamed to the
catalog grain from `gcp_project_id`, outputs untouched — all 8 inbound
FKs safe), `storage_class`, explicit `force_destroy` defaulting FALSE
(replaces the old hardcoded true — destroying a data-bearing bucket now
fails safe), UBLA, `public_access_prevention`, versioning, `autoclass`
(+ terminal class + a CEL guard against combining with SetStorageClass
lifecycle rules), complete `lifecycle_rules` (all three action types;
all condition criteria incl. matches_prefix/suffix, days_since_*,
num_newer_versions — numeric criteria as `optional` so a set 0 is
expressible, with `send_*_if_zero` handled in both engines), WORM
`retention_policy` (+ irreversible-lock semantics taught in comments),
`soft_delete_policy` (0-to-disable expressible), CMEK → GcpKmsKey FK,
`requester_pays`, `default_event_based_hold`,
`enable_object_retention`, `website`, `cors_rules`, `logging`
(log_bucket as a self-kind FK), `custom_placement_config` (exactly-two
regions), `rpo` (turbo replication), user `labels` (renamed from
`gcp_labels`), additive `iam_members` (replacing the authoritative
`iam_bindings` — the catalog's additive-grant doctrine), and `ip_filter`
(network-layer allowlist evaluated before IAM: public CIDR ranges +
VPC-network sources as GcpVpcNetwork FKs → `network_id`, with an
Enabled-requires-source CEL; present on the released 6.50.0 line —
schema-probe verified against the pinned provider).

**Recorded skips (docs/README.md):** bucket IAM binding/policy trio
(authoritative clobber semantics), bucket objects / notifications /
HMAC keys / managed+HNS folders / Anywhere Cache / Storage Insights
(independent-lifecycle kinds, deferred Tier-2), legacy ACL family
(superseded by UBLA), the three encryption enforcement blocks +
lifecycle size conditions (absent from the released 6.x line —
schema-probe verified against the pinned 6.50.0 provider schema).
