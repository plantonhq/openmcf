## Detailed Findings

### 1–2. Registry and Structure

✅ Enum 644 (data sub-band); `prerequisites: [GcpFirestoreDatabase]`;
full anatomy including `e2e/` (minimal composite-index scenario on the
database prerequisite chain).

### 3. Protobuf API Definitions

✅ Composite indexes as reviewable infrastructure (Firestore rejects
multi-field queries until a matching index exists): `database` ref with
"(default)" fallback, `collection`, query_scope
(COLLECTION/COLLECTION_GROUP/COLLECTION_RECURSIVE, default COLLECTION),
api_scope (ANY_API/DATASTORE_MODE_API, default ANY_API), `density`,
`fields[]` with exactly-one-role CEL per field (order XOR array_config
XOR vector_config with dimension ≥ 1 — the vector arm enables
nearest-neighbor queries). Full immutability and the
create-before-destroy rebuild behavior documented. Recorded skips
(released-schema-probe verified): `search_config` (geo/text specs),
`multikey`, `unique` — absent from released 6.50.0; `firestore_field`
single-field/TTL overrides stay unmodeled. 25-case spec test green.
