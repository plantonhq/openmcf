## Detailed Findings

### Protobuf API Definitions — validation quality note

The spec models a full `google_compute_security_policy`: ambient-optional
`project_id` ref, optional `policy_name` (RFC1035 CEL), `description`,
immutable `type` (CLOUD_ARMOR / CLOUD_ARMOR_EDGE / CLOUD_ARMOR_INTERNAL_SERVICE),
policy-level adaptive protection, advanced options (JSON parsing, logging,
user-IP headers), reCAPTCHA config, and inline `rules` with IP-based or CEL
matching, rate limiting, redirect, header injection, and WAF exclusions.
Message-level CEL enforces the API contracts pre-deploy: non-empty rule sets
must include the priority-2147483647 default rule; unique priorities;
action↔options coherence (rate_limit/redirect); match-mode exclusivity;
rate-limit key exclusivity; redirect target coherence; reCAPTCHA site-key
non-empty when set. reCAPTCHA site keys carry `sensitive_exempt_reason`
(public client identifiers). 79-case spec test.

**Session deliverables:** comprehensive spec rebuild; dual-engine
`security_policy.go` / TF modules with full rule dynamic-block parity; three
presets (basic IP allowlist, rate-limiting API, WAF OWASP protection);
`cloud_armor_policy.go` verifier (default-rule invariant + self_link match);
E2E `basic-allowlist` leaf scenario with run-scoped `policyName`.
