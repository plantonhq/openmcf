## Detailed Findings

### Protobuf API Definitions — validation quality note

The spec models one Cloud DNS record set — the (name, type) unit that answers
queries with either static RRDATA (`values`) or exactly one routing policy
(`wrr`, `geo`, or `primary_backup` with health-checked targets). Message-level
CEL enforces the API's exclusive contracts: values XOR routing_policy;
exactly-one routing style; geo-fencing only with geo entries; health-checked
targets require at least one ILB or external endpoint. Ambient-optional
`project_id` ref, required `managed_zone` ref (zone resource name, not DNS
name), passthrough `type` (any uppercase record type the API accepts), FQDN
`name` with wildcard/underscore support and composition hooks to
`GcpCertManagerDnsAuthorization` outputs, default `ttl_seconds` 300, and full
routing-policy sub-messages with FK wiring to `GcpHealthCheck`, `GcpAddress`,
`GcpVpcNetwork`, and `GcpProject`. 34-case spec test.

**Session deliverables:** rebuilt spec from zone-shell split; new
`record_set.go` Pulumi module and matching TF `main.tf`; three presets
(A-record, CNAME, weighted-canary); `dns_record.go` live verifier; E2E
`a-record` scenario chained to `GcpDnsZone` prerequisite.

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- Both engines map `google_dns_record_set` with identical project/zone/name/type
  resolution, static `rrdatas` XOR `routing_policy` dynamic blocks, and TTL.
- Routing-policy sub-messages (WRR, geo, primary/backup, health-checked targets,
  ILB frontends) translate identically on both engines.
- Outputs resolved from the created resource with matching keys: `fqdn`,
  `managed_zone`, `record_type`, `project_id`, `ttl_seconds`, and routing
  policy echo fields.
- `StringValueOrRef` refs resolve through the same `default_kind` wiring on
  both engines.

### Composition contract

Prerequisite: `GcpDnsZone` (registry + E2E chain). The record is the attach
point for certificate validation — `name`/`values` compose from
`GcpCertManagerDnsAuthorization` outputs (`dns_record_name`,
`dns_record_data`). Zones and records have independent lifecycles; this kind
owns only the record set, not the zone shell.
