### Protobuf API Definitions — validation quality note

The spec models 100% of the released 6.50.0 resource (schema-probe
verified): project (ambient), job name (optional with the metadata.name
fallback), location, unix-cron schedule (required — the provider marks it
Optional but the API rejects a standard job without one; honest pre-deploy
enforcement), time zone, description, attempt deadline, initial paused
posture, all three targets (HTTP with OAuth-XOR-OIDC GcpServiceAccount-ref
tokens, Pub/Sub with a GcpPubSubTopic ref resolving to the fully qualified
topic path, App Engine with routing), and retry config. Message-level CEL
enforces exactly-one-target and OAuth/OIDC exclusion pre-deploy; the
deprecated `deadline` alias is not modeled. 52-case spec test.

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- **The job-name fallback parity break is CLOSED**: the spec documents
  "empty job_name defaults to metadata.name" and Pulumi implemented it, but
  the Terraform module used the raw spec value — an empty job_name produced
  differently named jobs per engine. TF now resolves the identical fallback
  in locals (explicit conditional, not `coalesce()` — the empty-string
  trap). Proven live: the pubsub-target scenario omits jobName on both
  engines.
- Both engines enable `cloudscheduler.googleapis.com`
  (`disable_on_destroy=false`) and honor the ambient-project contract
  identically.
- Optional-field folding identical: time_zone/attempt_deadline sent only
  when set so the provider defaults (Etc/UTC, 180s) apply on both engines;
  `paused` sent only when true; retry dials use zero as the not-set
  sentinel; empty maps omitted.
- **Bridged-provider `deletion_policy` neutralized**: pinned to `DELETE`
  with a PARITY comment (absent from released 6.50.0).
- Outputs resolved from the created resource on both engines: `job_id`,
  `job_name`, `state` (present on released 6.50.0 for this resource —
  unlike the Cloud Tasks queue — so both engines export it).
- Neither kind supports GCP labels (API limitation) — documented
  identically in both modules.
- Zero PARITY-EXCEPTION comments needed.

### Composition contract

Four reference fields: `project_id` → GcpProject; both token
`service_account_email` fields → GcpServiceAccount
(`status.outputs.email`); `pubsub_target.topic_name` → GcpPubSubTopic
(`status.outputs.topic_id`, the fully qualified path the Scheduler API
requires — format live-verified). Registry gained
`prerequisites: [GcpPubSubTopic, GcpServiceAccount]` (both designed
compositions exercised live). No inbound proto FKs reference this kind.
