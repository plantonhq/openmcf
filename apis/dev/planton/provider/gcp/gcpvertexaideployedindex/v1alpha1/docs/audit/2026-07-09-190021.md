### Protobuf API Definitions — validation quality note

The spec models the placement resource at the released 6.50.0 floor:
required immutable `location`, `deployed_index_id` (letter-start regex in
CEL), FK refs to `GcpVertexAiIndex` (`index_id`) and
`GcpVertexAiIndexEndpoint` (`index_endpoint_id`), optional
`display_name` (immutable on this resource class — taught in spec),
automatic XOR dedicated sizing arms (replica bounds the only in-place
knobs), `deployment_group` with the group↔reserved-ranges pairing
contract taught, `enable_access_logging`, `reserved_ip_ranges` →
`GcpGlobalAddress.name` (Vertex peering ranges are global INTERNAL
VPC_PEERING addresses — FK-precision correction from the second pass),
and optional JWT `auth_config` (allowed_issuers → GcpServiceAccount
email refs + audiences). The spec header documents honestly that this
resource class carries NO labels and NO project field — platform label
attribution is impossible here. 34-case spec test (including the
dedicated-arm `max_replica_count > 1000` negative), all green.

### The sub-resource-ID hold — live-found, fixed, encoded

GCP holds a failed or still-undeploying `deployed_index_id` with a 400
("It will be deleted automatically, please retry again later or use a
different ID") — and the hold SURVIVES deleting the parent index
endpoint, so a fixed ID 400s across engines and back-to-back runs. The
scenario carries `deployedIndexId: planton_oss_e2e_${E2E_RUN_ID_UNDERSCORE}`
on the runner's new underscore token (the ID class forbids hyphens; the
engine suffix `-p`/`-t` would break the plain token). Live proof: Pulumi
passed the full ~34-min composed chain; Terraform passed after the fix
with the run-scoped ID `planton_oss_e2e_ca58ffe2_t`.
