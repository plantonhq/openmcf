## Critical Gaps

None open. One critical parity defect was found during this audit and fixed in the same
session (see Category 5b below for the full record):

1. **[FIXED] Pulumi `google_project_service` lacked `DisableOnDestroy: false`**
   - **Why it blocked:** The pulumi-gcp provider defaults `disableOnDestroy` to `true`. Destroying a Pulumi-provisioned GcpAddress would have disabled `compute.googleapis.com` for the ENTIRE project, breaking every other compute resource in it. The Terraform module explicitly sets `disable_on_destroy = false`, so destroy semantics diverged by engine — an outcome-changing divergence. (The Pulumi code comment already stated the false intent; the arg was simply missing.)
   - **What was done:** Added `DisableOnDestroy: pulumi.BoolPtr(false)` to the `projects.ServiceArgs` in `address.go`, matching the Terraform module and the sibling `GcpVpcNetwork`/`GcpProject` Pulumi modules. Release-equivalent build re-verified green after the fix.
   - **File:** `iac/pulumi/module/address.go`

✅ **In parity:**

  deliberately not modeled in the proto — documented in `docs/README.md` under
  "Deliberately not modeled", so it is a scope decision, not an engine divergence.

⚠️/❌ **Divergences found during this audit (now resolved):**

- **API-enablement destroy semantics** — Terraform set `disable_on_destroy = false`;
  Pulumi omitted `DisableOnDestroy`, inheriting the provider default `true`. Impact:
  **would misdeploy at destroy time** — a `pulumi destroy` of one address would disable
  the Compute Engine API for the whole project, silently breaking unrelated resources;
  a `tofu destroy` would not. The proto contract/intent (and the module's own comment)
  is destroy-safe enablement, so Pulumi was the incorrect engine.
  **Fix applied:** `DisableOnDestroy: pulumi.BoolPtr(false)` added in
  `iac/pulumi/module/address.go`; release-equivalent build re-verified green.

**Effect on score:** none post-fix — the divergence was corrected in-session, so
Categories 4 & 5 are not capped. Had it shipped, it would have been a Critical Gap
marking both IaC categories ❌.
