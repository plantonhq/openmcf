## Detailed Findings

### Protobuf API Definitions — validation quality note

The spec models one Certificate Manager certificate with managed XOR
self-managed arms (CEL-enforced). Managed arm: `domains` (wildcard CEL),
`dns_authorizations` refs to `GcpCertManagerDnsAuthorization` (mutually
exclusive with `issuance_config`; wildcards require DNS auth), or
load-balancer authorization when both omitted. Self-managed arm: PEM
certificate + `pem_private_key` (`sensitive`, PEM-framing CEL rejects swapped
material). Top-level: ambient-optional `project_id` ref, optional `cert_name`,
`description`, immutable `location`/`scope` (ALL_REGIONS⇔global CEL), user
`labels`. Split from hidden inline authorizations — certificates now reference
first-class `GcpCertManagerDnsAuthorization` resources. 22-case spec test.

**Session deliverables:** spec rebuild with DNS-authorization composition;
dual-engine `cert_manager_cert.go` / TF modules; three presets
(managed-dns-auth, wildcard-cert, self-managed-pem); preset rename from
legacy single-domain/wildcard/external-dns names; E2E `managed-dns-auth`
composed chain (zone → authorization → dns record → cert); `cert_manager_cert.go`
verifier with CREATION posture (not ACTIVE).

### Cross-Engine IaC Parity (Critical GATE)

**Parity verdict: PARITY ✅**

- Both engines map `google_certificate_manager_certificate` with identical
  managed/self-managed arm selection, DNS authorization ID resolution, scope,
  location defaulting (`global`), and labels merge (user first, platform
  `planton-ai_*` wins on conflict).
- `pem_private_key` masked identically on both engines (sensitive field).
- Outputs: `certificate_id` (full resource name), `certificate_name`,
  `state`, `domain_statuses`, managed/self-managed echo fields — resolved
  from the created resource on both engines.

### Composition contract

Prerequisite (registry): `GcpCertManagerDnsAuthorization`. Three-node
certificate flow: authorization → `GcpDnsRecord` (validation CNAME) →
certificate referencing `authorization_id`. The `certificate_id` output is
what target HTTPS proxies and certificate maps consume. Classic compute
certificates remain separate kinds (`GcpManagedSslCertificate`,
`GcpSslCertificate`).
