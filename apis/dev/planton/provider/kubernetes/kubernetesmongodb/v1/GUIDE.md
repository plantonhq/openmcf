# KubernetesMongodb Guide

The judgment this guide carries: this is the catalog's MongoDB — asking
for MongoDB needs no substitution (the engine is Percona Server for
MongoDB, fully MongoDB-compatible; every driver and tool works
unchanged, per the spec's own doc) — and the two composition decisions
that matter are where the operator watches and how applications receive
credentials.

## The operator must watch THIS namespace

KubernetesPerconaMongoOperator is the registry prerequisite, and its
default watch scope is its own namespace only. Two legitimate shapes —
databases co-located beside a per-namespace operator (the upstream
default posture) or one shared-chart operator watching cluster-wide —
are the
[operator guide](../../kubernetesperconamongooperator/v1/GUIDE.md)'s
judgment. Either way, the coupling never appears as a manifest edge:
reviewers verify the watch scope covers the database's namespace.

## Credentials are operator-generated — wire, never copy

The system-users Secret (`<name>-secrets`) is generated by the operator
under the naming contract on [reference.md](reference.md). Applications
read credentials from that Secret by reference (env valueFrom / mounts)
— copying generated passwords into application manifests breaks on the
first rotation and hides the dependency from the diagram.

## Namespace ownership

A database shares its namespace — with its application consumers, its
scheduled jobs, or its co-located operator. That is the multi-tenant
case where `createNamespace: true` is wrong: wire `spec.namespace` to a
dedicated KubernetesNamespace —
[namespace-ownership pattern](../../../patterns/namespace-ownership.md).

## On the diagram

Database and operator render as separate nodes (operator in whichever
layer the chosen shape puts it); application workloads draw namespace
and credential-consumption relationships around the database. A
sharded topology lives inside this one spec — it does not add nodes.

## Pairs well with

- KubernetesPerconaMongoOperator — required; placement judgment in its
  guide.
- KubernetesNamespace — the shared namespace's owner (pattern above).
- Application workloads — connect via the exported service handles and
  the operator-generated credentials Secret.
